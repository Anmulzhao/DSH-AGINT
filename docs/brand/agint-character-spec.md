## 0. 两条决策（老板 2026-10-04 拍板）

### 决策 1：公告按 TTL 轮播

上游公告只有一个槽（第 6.2 节）。AGINT 有四个状态源。
**做法：四个源轮流发，一次一条，按周期切换。**

参数：

| 项 | 值 | 出处 |
|---|---|---|
| 单条显示时长 | 10 s（建议） | 等于上游默认 TTL |
| 轮播周期 | 40 s（4 源 × 10 s） | 推导 |
| `ttlMs` | **必须 ≥ 轮播周期** | README.zh.md 第 216 行 |
| TTL 上限 | 7 200 000 ms | `announce.ts:45` |

**关键约束**：`ttlMs` 必须 ≥ 轮播周期。否则气泡会在轮到自己之前过期，出现断档。
例：4 个源各显示 10 s，`ttlMs` 要填 40 000，不能填 10 000。

**代价**：同一时刻只看到一条。同时多条异常时，看到哪条取决于轮播位置。
这是老板已知并接受的取舍。

### 决策 2：系统健康改走 skins 通道

`pet.announce()` 装不下系统健康：`kind` 限死三类，颜色限死三档且由宿主 CSS 硬编码（第 5.3 节）。
**做法：系统健康改走 `ctx.pet.setSkin()`。皮肤是 AGINT 自己的帧，颜色由 AGINT 自己定。**

通道已验证可用：

| 事实 | 证据 |
|---|---|
| 服务注册名是 `ctx.pet` | `agint-pet/src/index.ts:117` `export const name = 'pet'` |
| `PetService` 是 cordis 服务 | `src/service.ts:269` `class PetService extends Service` |
| `setSkin` 是公开 RPC | `src/service.ts:780` |
| `setSkin` 有 HTTP 面 | `src/routes.ts:609` |

**收益**：颜色不再受 `#7E98FF` / `#FBBF24` / `#F87171` 三档限制。第 5.2 节的 A 组色可以用上了。

**代价**（四条，都要接受）：

1. **皮肤落盘。** `service.ts:789` `this.ledger.setPetSkin()`。`announce` 是纯内存，皮肤不是。
   桌宠方案 P1 第 5 条「公告只存内存，不落盘」**只对 announce 成立，对皮肤不成立。**
2. **只在 idle 可见。** 皮肤只替换回待机的目标轨道（schema 第 327 行）。
   `thinking` / `tool` 等会话相位期间看不到状态。玩法轨道也不被替换。
3. **多 3 套帧的美术量。** default 用原 idle，另需 `degraded` / `failed` / `unknown` 三套 idle 帧。
4. **会覆盖用户手选。** 用户手动选的皮肤会被 AGINT 的状态切换顶掉。

### 决策 2 的连带结论：`announce` 不再承载系统健康

`announce` 保留，但**只用于语义天然吻合的数据**：

| 用途 | `kind` | 是否借道 |
|---|---|---|
| 今日消耗 / 本次会话开销 | `cost` | 正用 |
| 余额 / 配额剩余 | `balance` | 正用 |
| 系统健康、插件状态、cron | — | **不做。走 skins** |

**未验证**：AGINT 是否有真实的消费或余额数据。取决于 `agint.metrics.summary()` 返回什么。
没有就一条 announce 都不发。

全档位实测：

| 文件 | 画布 | 包围盒 | 原点 | 内缩（左/上） | 图形占画布 | ±2 邻域 |

### 4.1 三档等比，两档例外

按内缩占比看，256 / 512 / 1024 三档是**等比缩放**：

- 左右内缩稳定在 4.30% – 4.39%
- 上下内缩稳定在 5.08%

128 档略紧凑（3.91% / 4.69%）。64 与 32 两档是例外。

规则：

1. **256 / 512 / 1024 的等比值就是标准留白：左右 4.30%、上下 5.08%。** 新档位按它推。
2. **48 px 档的目标值**：左右内缩 48 × 4.30% ≈ 2 px，上下 ≈ 2.4 px，图形约 44 × 43，占画布约 82%。**这一档还没做。**
3. **96 px 档的目标值**：左右 ≈ 4 px，上下 ≈ 5 px，图形约 88 × 86，占画布约 84%。
   **未实测。** 由 64 档 83.54% 与 1024 档 81.95% 两端夹逼得出，属于外推，不是实测。
4. **32 px 不用。** 两个独立证据：图形只占画布 61.04%（其余档 82% 以上）；色彩清晰度 88.72%（门槛 95%）。
5. **64 px 用，但知道它在门槛下。** 图形占比 83.54% 正常，但色彩清晰度 93.71%，低于 95%。小尺寸下边缘会糊。

> **v0.2 纠错。** v0.1 写「32 与 64 两档的绝对内缩都是 4 px」。复测是 3 px（左/上）与 2–4 px（右/下）。
> v0.1 还写「小尺寸普遍偏轻」。复测只有 32 档偏轻。64 档 83.54% 比 1024 档 81.95% 还略重。

**B 组：公告气泡。** 由宿主 CSS 渲染，AGINT **不能**指定 hex，只能选 `tone` 三档之一。

> **v0.3 补充。** 决策 2 把系统健康从 B 组搬到了 A 组（第 0 节）。
> A 组因此从「装饰性用色」变成**状态承载的主战场**。5.2 那张表现在是真正的状态色表。

### 5.2 A 组：自绘资产用色（待美术确认）

对比度按 WCAG 相对亮度公式算。底色取品牌主色。

| 语义 | 色值 | 对 `#0A1B34` | 对 `#F5F8FC` |
|---|---|---|---|
| 品牌强调 | `#24D3E5` | 9.45 | 1.71 |
| 正常 | **`#FBBF24`** ⚠️ 见下 | 10.32 | 1.57 |
| 注意 | `#F5B851` | 9.73 | 1.66 |
| 故障 | **`#F87171`** ⚠️ 见下 | 6.23 | 2.60 |
| 休眠 | `#8A94A6` | 5.63 | 2.87 |
| 主色互查 | `#0A1B34` ↔ `#F5F8FC` | 16.17 | — |

规则：

1. **状态色只用于深底。** 对 `#0A1B34` 全部候选达到 5.63 以上，超过图形对象 3.0 的门槛。
2. **状态色不用于亮色底。** 对 `#F5F8FC` 全部候选都在 3.0 以下（最高 2.87），不合规。亮色底变体**还没做**。
3. **状态色不能单独承载语义。** 必须配形状或配文字。理由见第 8 节。
4. **「未读到」用琥珀，不用绿。** 这是 `agint-family-panel` 已确立的纪律：读不到就报未读到，不准用 0 冒充绿。

### 5.3 B 组：公告气泡只能选 tone

实证 `agint-pet/src/announce.ts:29`、`src/client/pet.module.css:707-720`：

|---|---|---|---|
| `ok` | `rgba(126,152,255,.45)` = **#7E98FF** | 无 | 正常 |
| `warn` | `rgba(251,191,36,.55)` = **#FBBF24** | `#fbbf24` | 警告 |
| `low` | `rgba(248,113,113,.6)` = **#F87171** | `#f87171` | 不足 |

规则：

2. **`ok` 是 dsh 蓝 #7E98FF，不是 AGINT 青 #24D3E5。** 品牌不一致。这是既定事实，写在这里让人知道。
3. **`tone` 缺省是 `ok`（`announce.ts:82`）。** 不发 `tone` 等于报「正常」。

### 5.4 状态到皮肤的映射（v0.3，主通道）

系统健康走皮肤，不走 tone。四个皮肤，对应 5.2 的 A 组色。

| AGINT 状态 | skin id | 主色 | 说明 |
|---|---|---|---|
| 全部正常 | `healthy` | `#24D3E5` 青 | 默认皮肤。可不显式声明 |

### 6.4 状态装饰按相位绑定，不能表达系统状态

实证 `agint-pet/src/contracts/status-decoration.ts:32-34`：

```ts
export type PhaseBindings = Partial<Record<ActivityPhase, PhaseSegment>>
```

`decoration.json` 是**独立 descriptor**，按 ActivityPhase 绑定帧段。未映射的相位默认 `hide`。
它跟 `kind` 没有任何关系。契约注释写死：*it never touches the pet manifests and never changes the bubble's semantics*。

三条推论：

1. 装饰**无法**表达系统级状态（cron 失败、插件红）。它只认 7 个相位。
2. 装饰是 **aria-hidden**。所以**不能**当无障碍的第二重表达。
3. 桌宠方案 P2 第 5 条「加 decoration.json 做状态装饰」能做，但只能按相位做。

契约约束（P2 直接用）：

| 项 | 约束 | 出处 |
|---|---|---|
| `license` | **必填**，空则整份拒绝 | `decoration.ts:137` |
| 资产格式 | 仅 `.webp` / `.png` | `decoration.ts:25` |
| 单帧时长 | ≤ 2000 ms | `decoration.ts:25` |
| `cell` / `columns` | ≤ 256 / ≤ 16 | `decoration.ts:23-24` |

### 6.5 其他规则

1. **`done` 与 `failed` 是单次轨道。** 播完回落 `idle`。契约支持 `loop: false` 加 `fallback`（schema 第 294-302 行）。
2. **不确定时用 `idle`。** 宁可静默，不要假装在忙。
3. **皮肤切换也是静默失败的候选。** `setSkin` 传了未声明的 id 只返回 `{ ok: false }`，不抛异常。
   **AGINT 侧必须检查返回值。** 不检查就等于状态切换全部失效且无感知。

## 7. 交付格式

选 `frames2d`，不选 `sprite2d`。

理由：`sprite2d` 的图集是固定 8 列 × 9 行，行序固定为 idle / running-right / running-left / waving / jumping / failed / waiting / running / review（README.zh.md 第 71 行）。这 9 个行名和 AGINT 的 7 个相位对不上，映射要扭曲。`frames2d` 每个相位一条独立轨道，帧时长可单独控制。

> 补充：README.zh.md 第 71 行还写了 **v2 图集是 11 行**——同样 9 行动画行，外加末尾 2 行视线跟随行，插件渲染 9 行、忽略视线行。结论不受影响，引用要完整。

契约约束（全部来自 `contracts/pet-manifest-v2.schema.json`）：

| 项 | 约束 | 行号 |
|---|---|---|
| `tracks` + `phases` | **frames2d 块必填这两项** | 246-249 |
| 帧目录 | `<dir>/<track>/<frame>.(webp\|png\|gif\|jpg\|jpeg)` | 250 |
| `dir` | 默认 `.`，只能用安全路径段 | 252-257 |
| `defaultFrameMs` | 16 – 5000，默认 200 | 258-263 |
| `tracks` | 1 – 64 条，小写 kebab，≤ 32 字符 | 264-268 |
| `frames` | 1 – 64 项，文件名不带路径段 | 273-282 |
| `frameMs` | 每帧时长，16 – 5000，**必须配等长的显式 `frames`** | 284-292 |
| `loop` | 默认 true，false 则末帧后进 `fallback` | 294-298 |
| `fallback` | 默认回落到 idle 对应轨道 | 299-302 |
| `phases` | 7 个相位，`idle` 必填 | 306-321 |
| `license` | **必填**，SPDX id 或自由文本，≤ 128 字符 | 44-49 |

帧时长的解析优先级（schema 第 250 行）：`frameMs[i]` > 文件名编码的 `<base>_<index>_<ms>` 后缀 > `defaultFrameMs`。

显示尺寸范围 32 – 1024 px（README.zh.md 第 182 行）。**取 96 px 作为 AGINT 桌宠的默认显示尺寸。** 96 px 在 32 px 禁用档之上，外推图形占画布约 84%（第 4 节规则 3）。**该档未实测。**

## 8. 无障碍

### 8.1 暗色变体内部对比度 1.71（v0.1 已有，保留）

`agint-icon-1024-onDark.png` 里 `#F5F8FC` 与 `#24D3E5` 并排出现，两者相对亮度对比 **1.71**，低于 WCAG 对图形对象要求的 3.0。亮色变体同一对色是 9.45，合规。

这是既有品牌资产的问题，不是新引入的。处置：**不要让语义只靠强调色承载。**

### 8.2 半透明描边把气泡对比度打到 3.0 以下（v0.2 新增）

第 5.3 节的三个 tone 都是**半透明描边**。叠在深底 `#0A1B34` 上后，实际呈现色远暗于纯色。

| `tone` | 描边 | 合成后色 | 对 `#0A1B34` 对比度 | 门槛 3.0 |
|---|---|---|---|---|
| `ok` | `rgba(126,152,255,.45)` | `#3E538F` | **2.33** | ❌ 不合规 |
| `warn` | `rgba(251,191,36,.55)` | `#8F752B` | 3.89 | ✅ 合规 |
| `low` | `rgba(248,113,113,.6)` | `#994F59` | **2.97** | ❌ 不合规 |

v0.1 只算了纯色对比度（#FBBF24 = 10.32、#F87171 = 6.23），结论「远超 3.0」在气泡链路上不成立。

规则：

1. **`ok` 与 `low` 的描边不可单独依赖。** 必须配文字。
2. 文字这层由宿主保证：气泡自带 `role="status"` 与 `aria-live="polite"`（`PetSprite.tsx:218`）。
3. **状态永远由颜色 + 形状 + 文字三重表达。** 装饰是 aria-hidden，不算第二重。
4. **skins 通道天生没有文字层。** 皮肤只是换 idle 帧，读屏软件访问不到。
   所以第 5.4 节规则 2 是硬要求：**四个皮肤必须靠姿态区分，不能只换色。**
   需要文字时，走 `announce` 补一条气泡。
5. **皮肤切换有可见延迟。** `setSkin` 写的是 ledger，浏览器侧 2 s 轮询（README.zh.md 第 216 行）。
   状态变化最多 2 s 后才显示。不要拿它报需要即时感知的事。

### 9.3 设计语汇（四方向共有）

1. **两色制**：深蓝做主体，青做唯一强调。青出现即焦点。
2. **环母题**：四个方向全是环。环是 AGINT 的核心图形。
3. **缺口母题**：环不闭合。断口、指针、菱形、独立的点，都是「环上的事件」。
4. **粗描边、无渐变、纯平**。
5. **几何极简**。元素数量少，笔画粗。

### 9.4 形式的第一性原理（v0.5 重写）

**三步论证。判决依据不是审美，是 `docs/evolution-framework.md` 第一章的五条工程不变量。**

**步骤 1：使命决定形式。**

`AGENTS.md:51` 实证 —— 智进的唯一使命是「在美的理念下**持续进化**」。

- 「持续」= 无终止项。
- 「进化」= 状态永不自同一。

⇒ 智进的存在方式是**过程**（becoming），不是**实体**（being）。

⇒ 给它一个固定不变的吉祥物形象，是**范畴错误**：把「正在成为」画成「已经是」。

**步骤 2：未完成必须是结构上的，不是修辞上的。**

一个完形加一句「我们还在进化哦」的文案 = 修辞上未完成，结构上完成。**那是撒谎。**

⇒ 形的定义必须**结构性地**包含未完成。

**步骤 3：母版已经给了这个结构，而且只有它给了。**

母版唯一表达「未完成」的元素 = 环的缺口。

v0.4 的三重错误：

| 动作 | 违反 |
|---|---|
| 把缺口降格为「能量口」 | 抛弃了唯一的未完成元素 |
| 加眼睛、身体、青点（元素 1 → 4） | **简洁 > 冗余** |
| 眼睛是拟人讨好 | **真实 > 讨好** |
| 静态吉祥物，等人看 | **主动 > 被动** |

### 9.4.1 核心命题

> **「智进」不是一个东西，是一条正在走的路。**
> **能画出来的不是它「长什么样」，是它「走到哪了」。**

### 9.4.2 两个先例（论证的根基，不是修辞）

**布朗库西《空间中的鸟》（1919）。** 抛光青铜。无羽毛、无喙、无翅。只有一道上升的弧。
布朗库西：*"我不是在雕鸟，我是在雕飞翔。"*

| 做法 | AGINT 对应 | 判决 |
|---|---|---|
| 雕一只鸟 | 造一个角色（v0.4 环灵） | 冗余 + 讨好 |
| 雕飞翔 | 画进化本身（v0.5） | 简洁 + 真实 |

**谢赫《古画品录》六法。** 第一法「气韵生动」，第三法才是「应物象形」。
⇒ 形的最高标准不是像不像，是**生气连贯**。
「一笔书」（王献之）一气不断 ⇒ 单笔不间断 = 气脉不断。

**「进」的义理。** 《易·乾》象传：*"天行健，君子以自强不息。"*
「进」的宾语不是终点，是行进本身。⇒ **形不得有终点。**

三条先例指向同一个形式：**一条不闭合、有方向、气脉不断的单笔路径。**

### 9.5 形式定义

**「智进」= 一条不闭合的单笔环形路径（open single-stroke loop）。**

四个构成要素。全部来自母版语汇（§9.3）。**零新增元素。**

| # | 要素 | 定义 |
|---|---|---|
| 1 | 路径本体 | 粗描边环形笔迹，**半径带低频扰动（§9.5.1 增强 A），不是几何正圆**。深蓝 `#0A1B34`（亮底）/ 青 `#24D3E5`（暗底） |
| 2 | 缺口 | 起笔端与收笔端之间的空缺。**永不闭合。** |
| 3 | 方向 | 收笔端固定在右上 45°（1:30 方向）= 前进方向。起笔端随状态移动，缺口角随之变化 |
| 4 | 渐宽 | 线宽从起笔端到收笔端递增 ⇒ 积累与生长 |

**不画的 —— 删除清单，比画什么更重要：**

- 不画眼睛。AGINT 没有眼睛。眼睛是讨好。
- 不画身体。不画脸。不画任何生物特征（耳、肢、尾、毛发）。
- ~~不画字母 A 的可识别字形（许可，见 §9.9）。~~ ⚠️ **这条禁令已撤销**（老板 2026-10-04 21:25，§9.9）。
  本形式（§9.5 单笔环形路径）**仍然选择不画 A** —— 这是形式选择，不再是许可约束。
- 不画装饰性高光、渐变、投影。

**做减法是本版相对 v0.4 的主要动作。** 直接兑现「简洁 > 冗余」与「真实 > 讨好」。

### 9.5.1 素材先例（v0.5 新增 —— 灵感来自素材本身，不是发明）

老板指示回看品牌资产找灵感。全部 12 张实读后（§9.2），v0.5 的形式在素材里**有四个先例**，
另提取出**两条增强**：

**先例（佐证 v0.5 方向不是凭空来的）：**

| v0.5 形式要素 | 素材先例 | 出处 |
|---|---|---|
| 沿路径渐宽 | 粒子环**粒子大小沿环渐变**（顶小右大） | `067dcf0f`（编辑稿） |
| 收笔端朝上 / 向前 | 实心盘负空间里挖出**向上箭头** | `b8ee79a8` |
| thinking 相位的短分支 | 网络图里一条**青色弦线**横穿环心直连 | `a10faa78` |
| 青色事件点 | 粒子环收敛版：青点**悬浮在缺口上方** | `067dcf0f` |

**增强 A（采纳）：路径不必是正圆 —— 加低频扰动，做成「不完美的环」。**

- 出处：网络图 `a10faa78` 的环是**不规则七边形**，不是正圆。
- 论证：正圆 = 几何完美 = 收敛 = 完成。**进化中的形应该带生成痕迹。**
  扰动是「持续进化」在形式上的微观兑现 —— 与缺口（宏观未完成）互补。
- 实现：`r(θ) = r₀ × (1 + ε·noise(θ))`，ε ≈ 0.03（低幅，可辨识但不破坏环感）。
  `noise` 用固定种子的低频噪声，**七相位共用同一个扰动函数** —— 形是「同一个体的不同时刻」，
  不是七个随机形状。
- 附带许可收益：扰动后的轮廓与母版正圆差异更大，进一步远离「描摹」。

**增强 B（v0.6 已实测，结论：不采纳，疑虑解除）：体量档。**

- 出处：实心圆盘 `b8ee79a8` 在小尺寸下的辨识度天然高于细描边。
- 疑虑：96 px 下 `w_start = r×0.18 ≈ 7 px`，可能偏细；任务栏 / 角落场景更明显。
- **v0.6 实测结论：疑虑不成立。** 96 档十轨全部可辨（§9.10），线宽不上调，
  实心填充不引入 —— 实心会把「路径」变成「盘」，回到被否决的实体化方向。
- 实心盘真正可取的是**负空间造型法**：如果未来需要第二重形状表达（如装饰层），
  用「挖空」不用「叠加」。记入备选，本轮不用。

**青色事件点（明确不采纳，理由记录）：**

粒子环的悬浮青点很诱人，但 v0.4 已因冗余删除同类元素，**不恢复**。
青点能承载的信息（当前相位）已由缺口角 + 线型完整承载。加回来是装饰，不是信息。
除非未来实测「蒙色后缺口角分辨不足」，否则维持删除。

### 9.6 七相位 = 路径的七种运动态

**不是七种表情。是同一条路径的七种运动状态。**

| 相位 | 路径运动 | 缺口角 θ | 线宽 | 附加 |
|---|---|---|---|---|
| `idle` | 静止，整体呼吸 ±1% | **θ_min** | 恒定 | — |
| `waiting` | 收笔端驻留微颤 ±0.5° | θ₀ | 恒定 | — |
| `thinking` | 内侧分出短支，试探后收回 | θ₀ | 恒定 | 1 条分支 |
| `tool` | 外接伸出线，伸 → 收循环 | θ₀ | 恒定 | 1 段工具臂 |
| `review` | 出现一个回折小环（自检查） | θ₀ | 恒定 | 1 个回折 |
| `done` | 收笔端向前推进一档 | θ₀ − Δ | +1 档 | — |
| `failed` | 收笔端之前断开，断端回缩变细 | θ₀ + 2Δ | −1 档 | 断口 |

**v0.6 更正：`idle` 的缺口角是 θ_min，不是 θ₀。**
理由：皮肤只替换 idle 轨道（`manifest-v2.ts:327` 实证），§9.7 规定 healthy = θ_min。
idle 与 healthy 是**同一条轨道**，两个表必须同值。θ₀（36°）是「投入工作」的中性开口，
idle（θ_min = 18°）比它更闭合 —— 健康时最完整，符合语义。

**关键决断 —— 对 v0.4 的自我纠正：**

v0.4 写 `done` = 缺口**闭合**。**这是错的。**

- 闭合 = 收敛 = 停止进化。
- 这与 `AGENTS.md:51`「持续进化」**直接矛盾**。

⇒ **`done` 的正确表达是「推进一档」，不是「闭合」。**
⇒ **缺口角硬下限 θ_min > 0，任何状态不得归零。**

**成功不意味着终结。** 这是本版最重要的一条形式规则。

### 9.7 四皮肤 = 靠线型区分，不靠颜色

| 皮肤 | 线型 | 缺口角 | 端点 |
|---|---|---|---|
| `healthy` | 实线 | θ_min（最小） | 两端清晰 |
| `degraded` | 中段虚线，**仍连通** | θ₀ + Δ | 两端清晰 |
| `unknown` | 起笔端渐隐消失 | θ_max（最大） | 起笔端 fade out |
| `failed` | 断成两段，端点错位 | — | 两端错开，不可接续 |

语义对应（不是拍脑袋）：

- `degraded` = 能力有缺口但**仍连通** ⇒ 虚线
- `unknown` = 看不到**来处**（已发生了什么不知道）⇒ 起笔端消失
  ⚠️ 不是「看不到前方」。前方本来就未知。未知的是过去。
- `failed` = **不可接续** ⇒ 断成两段且错位

**验收判据：灰度输出，抹掉全部颜色，只看线型仍可区分四态。** 满足 §12 验收第 7 条。

⚠️ **颜色不取消。** §5.4 的主色表仍然有效。**线型是叠加的第二重表达，不是替代。**
二者是**冗余编码**：任何一重单独失效（色盲 / 灰度打印 / 小尺寸线型糊掉），另一重仍可读。
这兑现验收第 14 条「每个状态的语义都有颜色以外的第二重表达」。

### 9.8 参数化 —— 这是工程收益，不只是美学

形由参数定义 ⇒ **帧可由生成器渲染。这是「简洁 > 冗余」在工程上的兑现。**

| 参数 | 含义 | 定稿值（v0.6，已实现验证） |
|---|---|---|
| 画布 | 渲染分辨率 | 256 × 256（显示 96 px）；`--canvas` 可出任意档 |
| `r₀` | 基准环半径 | 画布短边 × **0.39**。**v0.6 修正**：0.40 是未计线宽的粗值，含线宽后外缘包围盒达 86%。按 §3 实测 boxAreaPct 81.95% 反推：`2 × r₀(1+ε) + w_end` 为边长，令其平方 / 画布² = 0.82 ⇒ **0.39** |
| `ε` | 径向扰动幅度 | 0.03。`r(θ) = r₀ × (1 + ε·noise(θ))`；噪声 = 3 个整数频率正弦（k=2,4,6）固定种子叠加 ⇒ **沿环首尾连续，接缝无跳变**；七相位共用 |
| `w_start` | 起笔端线宽 | r₀ × 0.18（256 档 ≈ 18 px，96 档 ≈ 6.8 px） |
| `w_end` | 收笔端线宽 | r₀ × 0.26（渐宽，沿弧长线性） |
| `θ_gap` | 缺口角 | θ_min = 18°（idle/healthy）、θ₀ = 36°（engaged）、θ₀−Δ = 27°（done）、θ₀+Δ = 45°（degraded）、θ₀+2Δ = 54°（failed）、θ_max = 72°（unknown） |
| `Δ` | 档差 | **9°** |
| `θ_end` | 收笔端角位 | 固定 45°（右上）；waiting 微颤 ±0.5° 不改基准 |
| `dash` | 虚线段长 / 间隔 | **0.35 r₀ / 0.45 r₀**。**v0.6 修正**：视觉间隔 = 间隔长 − 线宽（每段圆头端帽各侵入 w/2），间隔必须显著大于线宽，否则糊成实线（实测踩坑）。仅中段 20%–80% 弧长虚线，两端实线 =「仍连通」 |

### 10.3 五条美学 → 五条语气规则（v0.5 新增）

依据 `docs/evolution-framework.md` 第一章。每一条都指明**什么是不美**。

| 宪法原则 | 语气规则 | 禁止（即「不美」） |
|---|---|---|
| 简洁 > 冗余 | 一句说完。不铺垫、不寒暄 | 排比、修辞、前摇 |
| 真实 > 讨好 | 报原始事实，含失败数据 | 软化、安慰、粉饰、卖萌 |
| 靠谱 > 聪明 | 事实 → 处置 → 下一步 | 俏皮话、机灵话、双关 |
| 主动 > 被动 | 异常主动报，报完给处置 | 等问、沉默是金 |
| 安全 > 效率 | 有风险先说风险 | 为「不打扰老板」压告警 |

**其中两条是对 v0.4 的修正：**

| v0.4 写法 | 违反 | v0.5 修正 |
|---|---|---|
| 「主动搭话：少」「值守不唠嗑」 | **主动 > 被动** | 沉默只在**无事且无进展**时允许。有异常必须主动说 |
| 「干燥的工程师冷幽默」 | **靠谱 > 聪明** | **不写幽默。** 幽默若有，应来自事实本身的荒诞，不是来自修辞 |

**三角色在语气上的体现**（身份公式的落地）：

- **守门人**：说拦截，**敢说不**。"这一步被门禁挡了。理由是 Z。"
