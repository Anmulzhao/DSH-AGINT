# 立项：K21「331 处 schema 欠账」是误报，真 bug 在别处（2026-10-21）

- 结论先行：**331 处不是欠账，代码是对的。** 真 bug 是**部署位 preset 的 25 个工具行 import 全炸**，已修。
- 起因：老板看到 `plugin-check.sh` 报「K19 违例：存在未声明 additionalProperties 的 object schema」，要求单独立项修。

## 1. K21 的前提是错的

K21（`test/schema-guard.test.mjs`）的注释写着：

> DSH loader 对 `output.schema` 走 `assertSupportedJsonSchema()` 直通校验，
> **不经过** `valueSchemaSpecToJsonSchema()` 编译器 —— 所以 raw 形态是硬要求。

**源码级证伪**（dsh 0.2.1-rc.2，`app.asar` → `dsh-tools/lib/types/json-schema.js`）：

```js
function defineTool(options) {
  const parameters = parameterSchemaSpecToJsonSchema(options.parameters);
  const outputSchema = valueSchemaSpecToJsonSchema(options.output.schema);   // ← 编译器在前
  ...
}
function valueSchemaSpecToJsonSchema(spec) {
  const schema = compileValueSchema(spec, "schema");
  assertSupportedJsonSchema(schema);                                        // ← 断言在后
  return schema;
}
```

编译器的 `allowRequired` 决定哪里能写 `required`：

| 位置 | `allowRequired` | 作者侧能写什么 |
|---|---|---|
| `properties.X`（对象属性的每一项） | `true` | **`required: true`（唯一正确写法）** |
| output.schema 的根 | `false` | 不能写 `required` |
| `array` 的 `items` | `false` | 不能写 `required` |
| `oneOf` 的分支 | `false` | 不能写 `required` |

⇒ **作者侧写 `properties.X.required: true` 是对的**：编译器把它收成父对象的 `required: ["X"]`；
反过来在根层写 `required: [...]` 才是 author error（`required must be true when present`）。

K21 按正则扫源码里的 `required: true` —— 扫的正是**唯一正确**的写法，于是造出 331 处假警报。

## 2. 实测：代码是对的

用**宿主真正在跑的那份** `dsh-tools@0.2.1-rc.2` 跑一遍每个插件的 `defineTool`：

| 范围 | 结果 |
|---|---|
| 仓库 `plugins/`（27 个 tools.js） | 27/27 编译通过，0 抛错 |
| 部署位 `.agint-bundle/plugins/` | 28/28 通过（含防空转自测） |
| 部署位 `profiles/desktop/plugins/` | 依赖树不全，见 §3 |

编译产物实测（`cron_list`）：

- 作者侧 `jobs: { required: true, type: 'array', items: {…} }`
  → 产物 `properties.jobs` **无** `required`，父对象 `required: ["jobs"]`；
- `items` 那层 `required: ["id","name","schedule","description","running"]`；
- `oneOf` 属性（`lastRunAt` / `nextRunAt` / `lastOk` / `lastError` / `lastResultSummary`）**全部没有** `required` 同级。

## 3. 真 bug：部署位 preset 的 25 个工具行 import 全炸

顺着 K21 的告警往下查，发现另一件更要命的事（**这才是「智进加载不出来」的第二个原因**）。

智进 preset 的 25 个工具行在部署位是**相对路径**：

```
../../profiles/desktop/plugins/agint-memory/lib/tools.js
```

这些文件按**裸包名** import 官方包（`@deepseek-ai/dsh-tools`），解析入口是
`profiles/desktop/plugins/node_modules/@deepseek-ai/`。

实测那个入口里**只有 3 个包**（`cordis` / `dsh-storage-domain` / `dsh-tools`），
而 `dsh-tools@0.2.1-rc.2` 的 `lib/index.js` 还裸 import：

```js
import { AnonymousEntries, NamedEntries, ScopedLayers, scopeOf, scopeTarget } from "@deepseek-ai/dsh-scope";
```

**`@deepseek-ai/dsh-scope` 连它自己的 `package.json` 里都没声明**（上游打包漏了依赖），
本机整条解析链上又没有它 ⇒

```
25/25 个工具行 IMPORT-FAIL  ERR_MODULE_NOT_FOUND  Cannot find package '@deepseek-ai/dsh-scope'
```

后果与 2026-10-06 的 dsh-tools stub 事故**同族**：智进 preset 挂得上，
但**一个 agint 工具都没有**，界面**没有任何报错**。

修法：把 mirror 位的 `@deepseek-ai` scope 换成指向 dsh 官方 scope 的**整链链接**
（与 bundle 位同形，一次给全 306 个官方包）。修完：

```
agint                relative rows= 25  ok=25  fail=0
agint-blockchain     relative rows=  6  ok= 6  fail=0
agint-investor       relative rows=  5  ok= 5  fail=0
agint-ops            relative rows=  7  ok= 7  fail=0
ALL: ok=43 fail=0
```

## 5. 留下的真教训

1. 判据要取自**被检查方自己的实现**（编译器 + 断言），不要用正则复述规则。复述错了就会造出假警报，然后有人去「修」本来正确的代码。
2. 护栏的报错文案必须与实际判据一致。K21 那次文案说 K19、真因是 K21，白查一轮。
3. 「三包名单」这种**白名单式**部署位规则是脆的：上游加一个依赖就全灭。判据应该是**能不能 import**。
4. 上游包漏声明依赖（`dsh-scope`）会直接放大成部署位的静默失效 —— 部署位必须能独立 import 通。
