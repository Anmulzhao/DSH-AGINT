> **来源**：Phase-3 设计方案 §4.3（官方市场接入准备，判定为 **Blocked**）。
> **性质**：本文件是**上报用**缺口台账，不含任何接入设计。

---

## 1. 为什么是 Blocked

「任何人可以安装 AGINT」这个目标，当前有**三条互相独立的硬阻塞**。它们不在 AGINT 手里，
所以本阶段只做「解除阻塞前能做的准备」，不做「解除阻塞后的设计」。

设计稿 §4.1 的原话是：本阶段只做元数据补全与缺口清单。

## 3. 本阶段已完成的可执行部分（对应 B5 / B6）

这两项是 §4.3 标注「可立即做」的，本轮已做完，并且**做成了机器可校验的**，不是人工核对一次就消失。

| 验收项（§4.4） | 落地方式 | 验证方式 |
|---|---|---|
| 1 元数据齐备 | `repository` / `homepage` / `bugs` / `keywords` / `engines` 补全 | `check-publish-safety.mjs` |
| 2 `private: true` 保留 | 未移除（B1 未解除） | 同上 |
| 3 `files` 白名单安全 | 11 条白名单，覆盖约 774 文件 | 同上（禁 `.bak`/`node_modules`/runtime 目录） |
| 4 依赖清单 | `docs/specs/dependency-inventory.json`（基于真实 `plugins/*/package.json` 扫描） | 人工核对 |
| 6 不启动接入设计 | 仓库内无 Registry / 市场客户端 / 上传代码 | `check-spec-consistency.mjs` grep |
| 7 Blocked 状态显式 | `INDEX.json` 的 `pendingSpecs` 含 `market-integration`，`status=BLOCKED` + 四条 `blockedBy` | 读 `INDEX.json` |
| 8 备份纪律 | 改 `package.json` 前留 `.bak-<ts>` | 文件检查 |

⭐ **新增的机器校验（§4.4 原文只写「人工核对」）**：

- 元数据字段**缺失即 ERROR** —— 这类字段删掉不会立刻出事，等出事时已在包上躺了很久。
- `keywords` < 3 个即 ERROR —— 2 个关键词等于检索不到。
- `engines.node = "*"` 即 ERROR —— 通配等于没声明约束。
- `engines.node` 与 `README.md` 声明的 Node 版本**冲突即 ERROR** —— 两份各说各话时安装器只认一份。
  反之 README 没写版本时**不报**（缺声明 ≠ 冲突）。

## 4. B8 对市场接入的特殊影响

若第二个使用方在**另一台机器 / 另一个 OS** 安装，以下硬编码路径会直接失效：

- `agint-wiki` 的 `root` 默认值 `/home/kylin/projects/DSH/wiki`
- `C3_GIT_REPOS` 的硬编码路径

⇒ **多机路径环境化是市场接入的隐性前置**，不只是内部工程债务。

> ⚠️ 这条已部分缓解但**未根治**：Phase 3 组 2 的导出工具链全部用 `REPO_ROOT = resolve(__dirname, '..')`
> 推导，**不再硬编码绝对路径**；但插件侧的历史硬编码仍在。
