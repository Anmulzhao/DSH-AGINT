# 经验教训 — v0.2 dream sweep 阈值决策的凭据澄清

> 写于 2026-08-20。给未来读到 commit `0adf37b` 的人解释：那条 commit message 引用 "2026-08-18 老板决策" 的来历、为什么没进 memory、以及如何补查。

## TL;DR

`0adf37b` commit message 中 `agint-dream/sweep.js` 改动的描述里写了"按 2026-08-18 老板决策对齐 OpenClaw"。这次老板审 commit 时发现该日期凭据**不可查**（memory_search 未命中），随即追问决策真实性。经当面确认：

- **决策真实发生**：老板认可阈值 0.5/1/1 → 0.75/3/2 的方向
- **决策日期不精确**：原 message 引用的 "2026-08-18" 实际是当时 agent 写 commit 时从某个旧 dream 复盘文档里读到的，未经验证
- **决策依据沉淀补做**：memory entry `dream-sweep-threshold-2026-08` 已于 2026-08-20 写入

## 教训

### 教训 1 — commit message 不应引用未沉淀的凭据

- commit message 里的"老板决策日期"必须能在 memory / wiki / 聊天记录中找到
- agent 写 commit 时容易从上下文里"读到一个日期"就写进去，但这个日期可能不可查
- **修复模式**：要么 (a) memory_write 先沉淀、再写 commit message 引用；要么 (b) commit message 用中性描述"按 OpenClaw 默认值对齐"，不引日期

### 教训 2 — 改老 commit message 在本环境风险高

参见 `memory: amend-old-commit-risky-in-current-env`。本环境 dumb terminal + EDITOR unset，反复尝试 rebase -i / commit --amend 均失败或带副作用。

**规避方案**：不修原 message，改走
1. `memory_write` 沉淀决策（含真实确认日期 2026-08-20）
2. 本文档作为梳理性 commit / 历史注解
3. 老 commit message 保留为"作者当时的意图陈述"

### 教训 3 — memory discipline 在 commit 之前

AGENTS.md §2 明确"查记忆"是接活第二步；但 commit 阶段的 discipline 缺失 — 没有强制要求 commit message 里的每个引用都先查过 memory。下次大改前考虑加一条 rule：commit message 含日期 / 老板 / 决策类引用 → 必须先 `memory_search` 命中，否则 commit message 走"中性描述"。

## 下次如何补查阈值决策

```bash
# 1. 决策本身

# → 命中 memory:dream-sweep-threshold-2026-08

# 2. 教训（commit 流程）
agint memory search "amend commit message 风险"
# → 命中 memory:amend-old-commit-risky-in-current-env

# 3. 原 commit 凭据链
git show 0adf37b --stat
# → plugins/agint-dream/lib/sweep.js + test/sweep.test.js
```
