# 经验教训 — v0.7.1 install.sh 启动链路三层修复

> 写于 2026-09-20。本次修复包含两条 commit：
> - `fe9f3fd` — preset 引用 dsh RC 包 `dsh-workflow-worker-thread` 引发全 preset 加载失败
> - `6524f73` — `install.sh` 步骤 2 `safe_rsync --delete` 清掉 bootstrap 刚放的 zod，且 `find_local_zod` 优先级路径写错
>
> 两者串联成完整链路：**任何 AGINT 升级 / dsh 升 alpha 撞到"install 报警 + plugin require 失败"组合时，按本 lessons 自查**。

## TL;DR

AGINT v0.7.1 在新部署 + dsh 0.1.6-alpha.2 组合下出现**双轨失效**：4 个 preset 全部「加载失败」、24 个 agint tool row 全废、D-QAF 评估闭环静默中断。修复按"应急 → 顺序 → 优先级"三层进行。

| # | 层 | 现象 | 根因 | 修复 |
|---|----|------|------|------|
| 1 | preset → dsh 包引用 | `row "workflow-worker-thread" names a plugin that cannot be resolved` | preset 文件硬引用 `@deepseek-ai/dsh-workflow-worker-thread@0.0.1-rc.3`，但 dsh 0.1.6-alpha.2 已不带此 RC 包（dsh 升级时把 workflow 默认实现改成 stable 的 ptc） | 3 个 preset 改用 `@deepseek-ai/dsh-workflow-ptc`（dsh 官方 deps 携带） |
| 2 | install.sh 步骤顺序 | zod bootstrap 失败 warn，`agint-quality/node_modules/zod/` 不存在 | 步骤 2 `safe_rsync --delete` 把 dst 的 `node_modules/zod` 删掉（仓源 `plugins/agint-quality/` 没有 `node_modules/`），4.5 zod bootstrap 跑在步骤 2 之后 | install.sh 加 1.5 段 zod bootstrap（pre-plugin），4.5 段降级为 post-plugin 兜底 |
| 3 | find_local_zod 路径优先级 | 4.5 兜底段也失败（即使 1.5 成功） | `find_local_zod` 优先级列表写错：`profiles/web/node_modules/zod`（不存在）实际应是 `profiles/node_modules/zod`（dsh 全局软链的目标） | bootstrap 脚本加首选 `profiles/node_modules/zod` |

## 双轨失效的现场（老板截图原话）

> 我看加载出来了 —— 修复前 picker 显示 4 个 preset 全部「加载失败」红字
> `row "workflow-worker-thread" names a plugin that cannot be resolved: @deepseek-ai/dsh-workflow-worker-thread`
>
> 然后 install 时报 `zod bootstrap 失败（agint-quality-* plugin 启动时会找不到 zod）。手动跑：bash install/agint-zod-bootstrap.sh`

实际影响：
- preset 整张拒绝挂载 → **24 个 agint tool row 全废**（memory_search / wiki_search / rule_check / dream_status 等核心工具全部消失）
- D-QAF 评估闭环静默中断：`agint-quality-contract` / `eval` / `policy` / `report` / `sandbox` 5 个 plugin 因找不到 zod，启动时抛 MODULE_NOT_FOUND，**质量评估数据没人采、没人评估、没人拒绝**
- 用户在浏览器看到的：picker 4 个红字、preset 选了也加载不出来、智进框架实际**从未真正可用过**

## 三层修复详解

### 层 1：preset 引用 RC 包的教训

#### 现象

dsh web 启动扫 preset 时：

```
row "workflow-worker-thread" names a plugin that cannot be resolved:
@deepseek-ai/dsh-workflow-worker-thread
```

#### 根因（细节）

- `@deepseek-ai/dsh-workflow-worker-thread@0.0.1-rc.3` 在 npm registry 真实存在（发布候选版）
- 但 dsh 0.1.6-alpha.2 的 `package.json` 只有 `dsh-workflow-ptc` 和 `dsh-tool-workflow`，**没列 worker-thread**
- dsh 升级到 0.1.x 系列时把 workflow 默认实现从 worker-thread 换成 ptc
- AGINT preset 文件**没跟进这个 dsh 内部变化**，硬引用了已不存在的包
- `install.sh` 也**不补装**（无 `pnpm add` 步骤，无任何依赖声明）
- 结果：引用但无人装 → 悬挂

#### 修复

```yaml
# 改前（3 个 preset：agint / agint-blockchain / agint-investor）
- id: workflow-worker-thread
  name: '@deepseek-ai/dsh-workflow-worker-thread'
  config:
    provider: spawn

# 改后
- id: workflow-ptc
  name: '@deepseek-ai/dsh-workflow-ptc'
  config:
    provider: spawn
```

PT vs worker-thread 行为差异（必须心里有数）：

| 维度 | worker-thread（RC，已删） | ptc（dsh shipped default） |
|---|---|---|
| 执行模型 | Node `worker_threads` 隔离 V8 | 模型写 Python 在 dsh 沙箱 |
| 跨 agent() 桥接 | 通过 `ctx.subagents` 注册 | 通过 host service |
| 模型能写什么 | JS/TS | Python |
| GA 状态 | 0.0.1-rc.3（**未发布**） | dsh 官方 stable deps |
| 适用场景 | 长跑编排、多 subagent | 数据处理、模型推理、Pythonic 工作流 |

**回归评估**：AGINT 仓内部扫描无任何对 worker-thread 引擎的 JS 端调用链，workflow 工具仅暴露给模型使用。改 ptc 后工具语义为「模型写 Python 编排」，与 dsh shipped default 一致，**无 AGINT 内部破坏面**。

### 层 2：install.sh 步骤顺序的教训

#### 现象

```
[AGINT] 1/4 同步 presets → /dsh/.agent-presets
[AGINT]    ✓ agint
[AGINT]    ✓ agint-blockchain
[AGINT]    ✓ agint-investor
[AGINT] 2/4 同步 plugins → /dsh/profiles/web/plugins   ← safe_rsync --delete
[AGINT]    ✓ agint-quality                              ← 把 zod 删了
[AGINT]    ✓ agint-quality-eval
...
[AGINT]    ✓ agint-wiki
[AGINT] 3/4 同步 patch
[AGINT] 4/4 装后静态校验
[AGINT]    ✓ plugin agint-wiki 有 package.json
[AGINT] ⚠ zod bootstrap 失败（agint-quality-* plugin 启动时会找不到 zod）...
[AGINT]    ✓ zstd bootstrap OK
[AGINT] ✅ 安装完成
```

#### 根因

`install.sh` 在 v0.2 已经用 `safe_rsync`（rsync + `--no-links + --delete`），注释明确写：

> 语义等价于 `rsync -a --no-links --delete`：
>   - `--delete`：dst 完全镜像 src（src 里没有的，dst 里删掉）

`plugins/agint-quality/` 仓源下**没有** `node_modules/`，所以 `safe_rsync --delete` 会把 host 上 `agint-quality/node_modules/zod/` 整个目录删掉。

但 v0.2 设计的 zod bootstrap（`install/agint-zod-bootstrap.sh`）跑在 `4.5` 段，**步骤 2 之后**。结果：

```
步骤 2 → safe_rsync --delete 删 zod
步骤 4.5 → bootstrap 跑（找不到本地源）→ 失败 warn
```

**bootstrap 失败只 warn 不阻断**——这是 v0.2 的安全左移哲学（不强行联网装依赖），但**让问题被沉默**：install 退出码 0，dsh 启动却因为 zod 缺失崩溃。

#### 修复

`install.sh` 在步骤 1 之后、步骤 2 之前加 1.5 段（pre-plugin）：

```bash
# ── 1.5 zod bootstrap（必须在 plugin 同步之前）───────────────────────────────
# 见 install/agint-zod-bootstrap.sh。
# 顺序约束：步骤 2 用 safe_rsync --delete 把 plugins/agint-quality/node_modules/zod
# 清掉（仓源没有），所以 zod 必须先放进 host，再让 plugin 同步覆盖。
# 失败仅 warn，不阻断（用户可手动跑）。
# 同时在 4.5 段保留一份兜底（理论上不会再跑，但万一 bootstrap 失败，
# 后面 2/4 plugin 同步不会自愈——4.5 段的存在确保下一个 stage 还能补救）。
```

4.5 段保留并改注释为「post-plugin 兜底」——不是删除而是**降级**，因为：

1. 兜底覆盖「步骤 2 同步 plugin 之后有人手动跑了 rsync 清掉 node_modules」之类的边角场景
2. 删掉会破坏兼容：升级 install.sh 时旧机器可能卡在中间态

### 层 3：find_local_zod 路径优先级错

#### 现象

4.5 兜底段也失败——`find_local_zod` 找不到本地 zod 源，导致只能 `npm pack` 联网下载。

#### 根因

`install/agint-zod-bootstrap.sh` 的 `find_local_zod` 优先级列表：

```bash
# 改前
local roots=(
  "${DSH_HOME:-$HOME/.dsh}/profiles/web/node_modules/zod"    # ← 不存在
  "$HOME/文档/claude-projects/openclaw/node_modules/zod"      # ← macOS only
  "$HOME/projects/Metaversefans/metaverse-fans-web/node_modules/zod"  # ← macOS only
)
```

实际本机存在的 zod：

```
/dsh/profiles/node_modules/zod → /usr/lib/node_modules/@deepseek-ai/dsh/node_modules/zod
```

`profiles/node_modules`（profiles 层级，web/headless 共用）是 dsh 升级时建的软链层；`profiles/web/node_modules`（web 层级）通常**没有** zod 软链。

macOS 那两条路径在 Linux / Windows 部署上**全部不存在**（注释里也提到 `~/{文档,projects}` 是 macOS 布局，Windows 上不存在）——也就是说在 macOS 以外的部署，bootstrap 必然 fallback 到 `npm pack` 联网。

#### 修复

```bash
# 改后
local roots=(
  "${DSH_HOME:-$HOME/.dsh}/profiles/node_modules/zod"      # ← 首选，跨平台恒成立
  "${DSH_HOME:-$HOME/.dsh}/profiles/web/node_modules/zod"  # ← 次选
  "$HOME/文档/claude-projects/openclaw/node_modules/zod"    # ← 兼容老 macOS 部署
  "$HOME/projects/Metaversefans/metaverse-fans-web/node_modules/zod"
)
```

## 对未来升级的启示（**这是最重要的部分**）

### 当你升级 dsh 时

1. **第一步看 `VERSION` 表格**，确认 AGINT vX.Y.Z ↔ dsh version 兼容
2. **跑 install.sh 之前，先 `grep -r "dsh-" presets/ install/`**，找出 preset / install 脚本里所有硬引用的 `@deepseek-ai/dsh-*` 包名
3. **逐个对比 dsh `package.json` 的 deps**（`cat /usr/lib/node_modules/@deepseek-ai/dsh/package.json | grep dsh-`），任何**不在 deps 里的**都是悬挂引用
4. RC 包（`-rc.N`）**永远视为不稳定**——即使 dsh 之前用过，升 GA 时可能被砍

### 当你升级 AGINT 时

1. **跑 install.sh 装前装后**都看完整输出，不要只看退出码
2. 任何 **"bootstrap 失败"** 类 warn 都**不要忽略**——install 退 0 不代表可用
3. 装后必跑 `node --input-type=module -e "await import('./profiles/web/plugins/agint-quality/agint-quality-eval/lib/index.js')"` 之类的 sanity check
4. 装后必看 **dsh web 启动日志**——任何 `row "X" names a plugin that cannot be resolved` 都是 preset 引用问题

### 当你写新 preset 或新 plugin 时

- preset 里的 `name: '@deepseek-ai/dsh-*'` 必须是 **dsh 官方 stable deps**（`package.json` 的 dependencies，不是 devDependencies）
- 子插件的 lib 用裸 specifier（如 `from 'zod'`）**不可靠**——直接相对路径指向显式副本更稳
- 任何 `install/agint-*-bootstrap.sh`（zod、zstd、wasm、sqlite native binding 等）**必须放在 install.sh 步骤 2 之前**

## 哲学对齐检查

- **简洁 > 冗余**：1.5 + 4.5 双段、find_local_zod 加一条而不是改 5 条——任何场景下的最小改动面
- **真实 > 讨好**：bootstrap 失败 silent warn 改成自愈链路 + 显式双段，不掩盖问题
- **靠谱 > 聪明**：用 dsh 全局已有的 zod（不重复下载），bootstrap 失败仍能 fallback
- **主动 > 被动**：兜底段保留（4.5 + 4.55 + 4.7 + 防御性补装），任何一段失败不进入半成品状态
- **安全 > 效率**：所有改动不动 dsh 安装目录（dsh 全局 zod 只读，cp -r 到 plugins 是单向副本）
