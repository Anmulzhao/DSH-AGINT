# 经验教训 — v0.4 agint-wiki Windows path-escape 误报

> 写于 2026-09-04。agint-wiki 在 Windows 上所有 `wiki_write / wiki_read` 全部抛 `path escapes root`，但源码 `clean()` 的越界检查逻辑看似正确。根因：跨平台路径分隔符不一致。同 v0.3 教训：**「profile 级插件挂载即全挂」**模式。

## TL;DR

agint-wiki 的 `clean()` 用 `abs.startsWith(root + '/')` 做越界检查，Linux/macOS 上 `resolve()` 返回 `root/foo/bar.md`（正斜杠），`root + '/'` 是 `root/`，匹配。Windows 上 `resolve()` 返回 `D:\foo\bar.md`（反斜杠），`root + '/'` 变成 `D:\foo\`（末尾是反斜杠），**`D:\foo\bar.md` 不以 `D:\foo\` 开头**，永远 false → 所有 forward-slash 相对路径写入被误判越界。

| 维度 | 内容 |
|---|---|
| 现象 | Windows 上所有 `wiki_write` / `wiki_read` → `Error: agint-wiki: path escapes root (got "xxx.md")` |
| 触发条件 | Windows 上调 `wiki_write/read/list/search/lint` 即触发；Linux/macOS 正常 |
| 根因 | `abs.startsWith(root + '/')` 在 Windows 上因分隔符不一致永远 false |
| 修复 | 把 `root` 和 `abs` 都规范化为正斜杠后再比较；不削弱安全（仍拒 `../`） |
| 持续时间 | ~10 分钟定位 + 5 分钟修复 + 5 分钟写 smoke |

## Bug — Windows 路径分隔符导致误报越界

### 现象

`dsh web` 在 Windows 启动后，**所有 session、所有 preset** 的 `wiki_write` / `wiki_read` 都报：

```text
Error: agint-wiki: path escapes root (got "hello.md")
    at <agint-wiki dist>/lib/index.js:40
```

最初以为是 sandbox / file policy 问题，但都不是。错位在 `plugins/agint-wiki/lib/index.js:40`：

```js
if (abs !== root && !abs.startsWith(root + '/')) throw new Error(`agint-wiki: path escapes root (got "${p}")`);
```

`abs` 来自 `resolve(root, trimmed)`，**Windows 上返回反斜杠分隔路径**。

### 根因

| 平台 | root | abs | root + '/' | abs.startsWith(root+'/') |
|---|---|---|---|---|
| Linux/macOS | `/srv/wiki` | `/srv/wiki/hello.md` | `/srv/wiki/` | ✅ true |
| **Windows** | `D:\srv\wiki` | `D:\srv\wiki\hello.md` | `D:\srv\wiki\` | ❌ **false**（分隔符混搭） |

Linux/macOS 上 `resolve()` 返回正斜杠，`root + '/'` 自然衔接；Windows 上 `resolve()` 返回反斜杠路径，`root + '/'` 末尾加的是正斜杠，混搭后**永远是 false**。

Loader 阶段不报错（不会真去读文件系统），运行时每个工具调用都炸。

### 排查路径

| 实验 | 结果 | 结论 |
|---|---|---|
| Linux 上跑 smoke，forward-slash 路径 | ✅ 正常 | Linux 没暴露 |
| Windows 上跑 smoke，forward-slash 路径 | ❌ 全炸 `path escapes root` | 锁定平台相关 |
| `path.resolve('D:\\foo', 'bar.md')` 在 node REPL 跑 | 返回 `D:\foo\bar.md` | 确认 Windows 反斜杠 |
| 用 `path.normalize('D:\\foo\\')` 看末尾字符 | `\`，**不是** `/` | 锁定拼接 bug |

### 修复

```diff
 function apply(ctx, config) {
   const root = resolve(config.root);
+  // v0.4 fix: normalize to forward slashes for cross-platform startsWith
+  const normRoot = root.replace(/\\/g, '/');
   const clean = (p) => {
     const trimmed = String(p ?? '').replace(/^\/+/, '');
     if (!trimmed.endsWith('.md')) throw new Error(`agint-wiki: path must end with .md (got "${p}")`);
     const abs = resolve(root, trimmed);
+    const normAbs = abs.replace(/\\/g, '/');
-    if (abs !== root && !abs.startsWith(root + '/')) throw ...
+    if (normAbs !== normRoot && !normAbs.startsWith(normRoot + '/')) throw ...
     return { rel: trimmed, abs };
   };
```

关键点：
1. 规范化比较，但**仍用 `resolve()` 得到真实绝对路径**（避免 symlink 绕过）
2. **不削弱安全**：`../escape.md` 仍被 `resolve(root, '../escape.md')` 解析到 root 之外 → `normAbs` 不以 `normRoot + '/'` 开头 → 仍 reject
3. 注释说明为什么需要这一步（避免被未来的「简化」重构掉）

提交前全测：

| Case | 期望 | 实际 |
|---|---|---|
| `write('hello.md', c)` + `read('hello.md')` | ✅ round-trip | ✅ |
| `write('sub/dir/note.md', c)` + `read('sub/dir/note.md')` | ✅ nested | ✅ |
| `write('/leading.md', c)`（leading `/`） | ✅ stripped | ✅ |
| `write('../escape.md', c)` | ❌ reject `path escapes root` | ✅ |
| `write('../../etc/passwd.md', c)` | ❌ reject `path escapes root` | ✅ |

## 元教训 — 为什么这次没拦住

1. **8 维度 + 9 维度 lint 不覆盖跨平台**。contract / storage / deps / permissions / lifecycle / tests / docs / changelog + runtime-contract 都是平台无关的，**没有「跨平台 fixture」维度**。plugin 在 Linux/macOS 上跑测试全绿，但用户在自己 Windows 上一调就炸。

2. **「仓内 master 一直绿 ≠ 跨平台可用」**。AGINT 当前没跑 Windows CI，22+ 个 plugin 都是 Linux 开发，Windows 是新暴露面（DSH web 在 Windows 上首次正式跑就是这次 session）。

3. **plugin-preflight 的 smoke 模板只覆盖 happy path**。原 SKILL.md 第 2 步说「验证三件事：加载不抛 / apply 不抛 / waterfall 决策正确」，没强制要求「forward-slash + native-sep + ../escape 负向」。结果这种「**只在某平台暴露**」的路径 bug 漏到 prod。

4. **同 v0.3 模式**。v0.3 tools-waterfall 是「**profile 级挂载即炸**」，v0.4 wiki-path-escape 是「**profile 级首次 Windows 调用即炸**」。共同点：
   - 在 loader / 静态 lint 阶段**不报错**
   - 运行时**对所有 session 全炸**
   - 22+ plugin 共享 profile，**任何一个错就全挂**
   - 修复后必须**同步 runtime 副本**（首次同步即首次运行即首次炸）

## 预防机制

### plugin-preflight 第 2 步补强：跨平台 fixture

`presets/agint/skills/plugin-preflight/SKILL.md` 第 2 步新增子节：

> 若 plugin 的 `permissions.fs` 非空，smoke **必须**额外覆盖：
> - forward-slash 相对路径（典型：模型/工具传参风格）
> - native-sep 根 + 正向 round-trip
> - `../escape` 负向（路径安全不能因 fix 而削弱）

参考模板见 `plugins/agint-wiki/test/smoke.mjs`。
