# 经验教训 — 打开 `subagent_codex` 与一路上的取证失误

> 写于 2026-10-02。一次「给创造模式开一个工具」的小任务，暴露出比工具本身更值得记的三件事。
> 相关规约见 `docs/agent-collaboration.md` §6.5；Codex 调用 SOP 见
> `docs/operations/codex-handshake-20260821.md`。

## TL;DR

真正的教训不是某个技术点，是同一件事重复了三次：**差点把「看起来对」当成「查过了」**。

| # | 教训 | 实证 | 正确做法 |

| 1 | 手里已经有两个矛盾答案时，别挑一个继续 | 同一份会话日志同时命中 `"agentPreset":"agint"` 与 `"agentPreset":"cordis"`，我只取一个，前后说了两次错话 | 矛盾出现 = 还没查完。唯一动作是停下来解决矛盾 |

## 一、三个错，逐个复盘

### 错 1 — 手里有两个矛盾答案，我挑了一个就往前走

**经过**：老板说「我不是智进，我是创造模式」。此前我先说「本会话是 agint preset」
（依据：会话日志首行 `"agentPreset":"agint"`），紧接着又说「本会话不是 agint 组合的」
（依据：44 个工具里没有 `memory_search` 等 agint 工具）。**两次都错。**

真相是 `cordis` preset，显示名「创造模式」，依据：

```
dsh-client-ui-agent-preset/lib/client.js:315  →  presetCordisName: "创造模式"
```

**根因不是判断力差，是没处理矛盾**：第一次 grep 会话日志时，输出里**同时**出现过
`"agentPreset":"agint"` 和 `"agentPreset":"cordis"` 两个值。两条候选摆在那儿，
我却只盯着其中一条往下推，后面所有的分析都建在流沙上。

> **规则**：同一个问题出现两个候选答案时，正确动作是**解决矛盾**，不是**挑一个**。
> 两个候选值 = 证据还没查完，不是「大概率是哪个」。

### 错 2 — 取证做了，但没写进结论

`agint-rules` 两次提醒我未取证的断言（「无」「全部」）。其中一条是「8899 无监听」。

讽刺的是**我确实查过**——`ss -ltn | grep 8899` 跑过，0 命中。问题不在取证，
在于**结论句里没带痕迹**。这是比「没查」更隐蔽的坏状态：它让下游无法判断你是查过还是猜的。

> **规则**：取证的标准不是「我做过了」，而是「**读你结论的人能复核**」。
> `没有 X（grep N 行 / ls 输出 Y / 实跑输出 Z）` 才是完整结论；
> 没查就写「我还没验证」。

### 错 3 — 拿旧文档当当前真相

`docs/operations/codex-handshake-20260821.md` §3 第 2 点与 §5 都写了
「Codex session id 不可见（端点不暴露）」。我第一反应是沿用这条。

实测**取得到**——`codex exec` 的 **stderr 横幅**里直接打印：

```
session id: 01a0fa3b-e261-7f32-a4f9-77725b909747
```

更可能的根因不是「端点变了」，而是**观测位置错了**：横幅走 stderr，而原文档的示例
（§2.1/§2.3）只示范了 stdout 的用法。

> **规则**：历史文档是**事实记录**，不是缓存。引用它的前提是先验它还成立。
> 该文档自己的规矩是「不删旧结论，只并列更正」——两份并存比偷偷改掉有用。

## 二、三个真正管用的做法

### 做法 1 — 用「构造性证明」代替「看着对」

Loader 的 preset 覆盖是 **`config` 整块替换**（不是深合并），所以不能只写一行。
而官方 `presets/cordis.patch.yml` 里有 **4 处 `!!js` 表达式**（第 25/28/147/154 行）——
用 YAML 解析器读进来再序列化，会把这些表达式改坏。

改用**纯文本手术**：逐行搬官方文件，只删 `tool-subagent-codex` 底下那一行
`disabled: true`，并让脚本断言：

```js
overrideBody === expectedFull.replace(removedLine + '\n', '')
```

「与官方文本的差异**恰好是那一行**」——这比人眼看 154 行 diff 可靠得多，因为它把
「我以为只改了一处」变成了机器可判定的命题。

配套纪律：写盘前查结构 → 先备份 → 写盘后**把文件读回来重新解析核对** → 报回滚命令。

### 做法 2 — 工具侧做不到，立刻说做不到

`bin/dsh-direct.mjs` 需要 launch token。查证：`ps -eo args` 里宿主命令行是
`node .../bin/dsh web`，**不带 token 参数**；`find /tmp ~/.dsh ~/.cache -maxdepth 3
-name "*dsh*log*"` **0 命中**。没有 token 那条路就是死的。

我停在这里报告了，没有继续去别处翻凭据。

> **规则**：「我还没验证」是一句合法且专业的结论。
> 为了给出一个完整答案而去做不该做的动作，是更贵的错误。

### 做法 3 — 守住「服务活着 ≠ 行为正确」

`plugin_manager list_plugins` 显示 `include:subagent-spawn-in-process-codex` 是
`enabled: true, fiberPhase: "active"`。这只证明 **fiber 在跑**，不证明工具会调通。

真正闭环是三步：

1. 重启 dsh（宿主 10:32:52 启动，晚于覆盖写盘的 09:45:02）
2. `Tool.listTools` 命中 `subagent_codex`（重启前：44 个工具里 0 命中）
3. **真调一次** —— 子 agent 回报「跑在 DeepSeek provider 上，模型 MiniMax-M3.1-Flash-Preview」

第 3 步的回报还顺带验证了文档里那句警告是真的：**它不是 Codex CLI**。

## 三、跨 agent 协作的两条

### 每次 `codex exec` 都是冷启动

Codex 明确说「**我是新会话，无上次上下文**」，并拒绝凭印象设计，
理由是「直接读 `plugin-check.sh` 的现有编排比凭印象可靠」。

这条比它的设计本身值钱——**它没有拿「我记得」当事实**。反过来对 DSH 侧是同一条约束：
不要假设它记得上一轮结论，要接续必须把上下文写进 prompt。

### 名字对齐 ≠ 能力对齐

`providerName: codex` 注册的是 `@deepseek-ai/dsh-subagent-spawn-in-process`，
跑的是**进程内 DSH agent**，与 codex CLI 无关。名字对齐只是为了匹配 preset 里那个既有行。

> **规则**：起名要让人一眼看出背后是什么。否则半年后，连自己都会被骗——
> 包括被 `list_subagent_models` 这类只反映 LLM 路由、不反映 subagent 后端的接口误导。

## 四、留一句给自己的

这轮在同一件事上反复摇摆（先说 agint、再说不是 agint、又确认是 cordis），
根子都是**急着给结论，而证据还不够**。
而每次真正把工具跑一遍、把断言写进代码，结论立刻就稳了。

> **判据**：能不能用一句话说出「我凭什么这么说」——
> 说不出，就还没查完。
