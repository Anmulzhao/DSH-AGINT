# 经验教训 — v0.1 安装与加载三个 bug

> 写于 2026-08-18。一次完整 AGINT 安装调试过程的实录与教训,供未来升级、装新机、调试 dsh 集成时参考。

## TL;DR

AGINT 第一次在新装的 dsh 上跑挂,排查过程修了三处问题:

| # | 现象 | 根因 | 修复 |
|---|------|------|------|
| 1 | `dsh web` 启动失败 `failed to parse overlay ... cordis.patch.yml` | `install/install.sh` 把仓库 patch 整段 append 到 dsh patch 末尾,但仓库 patch 顶层**不是** `[ ]` 包装,而是扁平的 `- xxx` 列表,造成 YAML 顶层混了两个数组,解析失败 | install.sh 改用括号平衡 + 零缩进项识别,正确合成 dsh patch(扁平拼接,不强行加 `[ ]`) |

| 3 | `MODULE_TYPELESS_PACKAGE_JSON` warning: agint-rules / agint-quality 没有 `package.json` | Node.js 检测到 ESM 语法后**二次解析**,性能开销 + 噪音 | 给两个插件补 `package.json` + `"type": "module"` |

## Bug #1 — install.sh patch 合并逻辑错误

### 现象

```
Error: dsh: failed to parse overlay /home/anmul/.dsh/profiles/web/cordis.patch.yml:
YAMLException: end of the stream or a document separator is expected (17:1)
```

或者

```
YAMLException: missed comma between flow collection entries (5:1)
```

### 根因

我之前版本 `install.sh` 用「整段 append」:dst 已有内容(注释 + `[]`)后,把 `src_text`(另一个完整 patch)直接拼到末尾。

但是:
- dsh web 解析的 `cordis.patch.yml` 顶层是 **YAML 自动数组识别**(以零缩进 `- ` 开头的行识别为数组项)——`[]` 是空数组的写法,但**只要有任何 `- ` 行,顶层就是 block-style 数组,不需要 `[]` 包装**(参考 `@deepseek-ai/dsh-base/cordis.patch.yml`)。
- 仓库 patch 内容是一个 `- insert: [10 个 id 子项]` 段。
- 把 dst 的 `[]` 和 src 的 `- insert:` 段直接 append,结果是:注释头 + `[]` + `- insert:` ——**YAML 顶层混了一个空数组和一个数组项,无法解析**。

更糟的:原脚本的兜底(发现 src_text 已经 in dst_text → 跳过)没考虑到「src_text 被破坏性截断」的情况——只会出 YAML 报错,**不会跳过**。

### 修复

`install.sh` 的 Python 段重写为:
1. 用括号平衡找顶层 `[ ]` 区间(若没有就当作「整段是扁平列表」)。
2. 切出每个零缩进的顶层 list 元素(`- xxx` 起始)。
3. 合成时:**dst 自己的注释头(去掉 `[]` 空数组) + 自己的非 agint 列表项 + src 的 agint 列表项**,直接拼接——**YAML 顶层靠自动识别,不强行加 `[ ]`**。
4. 幂等检查改为「dst 端所有 agint id 与 src 是否一致(忽略顺序)」,不依赖文本子串包含。

### 教训

- **不要假设目标 patch 文件的格式**——`cordis.patch.yml` 是「数组」,但不是「flow-style `[ ]`」数组,而是「block-style 自动识别」数组。
- **修改其他系统的 patch 文件,先看它自己内部的 bundle patch 怎么写的**(@deepseek-ai/dsh-base/cordis.patch.yml 是参考实现)。
- **PyYAML safe_load 不能解析 `!!js` tag**,所以不能用 yaml 模块;必须纯文本 + 括号平衡。
- **正则 `\s*\[` 不匹配 `[]`**——`\[` 之后 `\s*` 是 0 长度匹配,然后 `$` 要行尾,但 `]` 还在。**正确写法是 `^\s*\[\s*\]\s*$`**。

## Bug #2 — inject 漏声明

### 现象

```
agint-quality-eval: scheduler init failed cannot get property "timer" without inject
```

### 根因

`plugins/agint-quality/agint-quality-eval/lib/index.js` 第 39 行:

```js
const inject = [];
```

但 `lib/scheduler.js` 的 `WeeklyScheduler` 用 `ctx.setInterval(...)`,这是 cordis-plugin-timer 提供的 API。Cordis loader 检测到 plugin 访问未 inject 的 ctx 属性,**直接抛错**(即使外层 try/catch 包了也会先抛)。

对比 `plugins/agint-cron/lib/index.js`:

```js
const inject = ['timer'];  // 正确
```

### 修复

`inject = ['timer']`。

外层 try/catch 改为 `console.warn` 而非 `error`——timer 不在时降级到「不自动调度,Service 仍可手动 runNow()」,而不是失败报错。

### 教训

- **Cordis plugin 用任何 `ctx.xxx`,xxx 都必须在 `inject` 数组里声明**——除了已经在父级 loader 提供的核心 service。
- **AGINT 8+1 个 plugin 里,凡是用了 `ctx.setInterval / setTimeout` 的(cron、quality-eval),都需要 `inject: ['timer']`**——这应该作为 plugin 模板的强制项,而不是每次现想。
- **`agint-dream` 也写了 `inject = []`,但用 `ctx.setTimeout` 是不**——值得排查(它可能在 `apply` 内的某个分支)。
- 教训应该进 `docs/plugins/agint-quality-eval.md` 和未来 lint 规则:`lint-agint.mjs` 应该加一条 `inject-must-include-timer` 当 plugin 用了 setInterval/setTimeout 时。

## Bug #3 — 缺 package.json 触发 Node 二次解析

### 现象

```
(node:1534906) [MODULE_TYPELESS_PACKAGE_JSON] Warning: Module type of
file:///home/anmul/.dsh/profiles/web/plugins/agint-rules/lib/index.js is not specified
and it doesn't parse as CommonJS.
Reparsing as ES module because module syntax was detected. This incurs a performance
overhead.
```

### 根因

AGINT v0.1 / v0.1.1 的 `plugins/agint-rules/` 和 `plugins/agint-quality/` 目录下**根本没有 `package.json`**。其他插件(`agint-memory` / `agint-cron` 等 8 个)都有,声明了 `"type": "module"`。

Node.js 检测到 `import` 语法但没有 `"type"` 字段时:**先按 CommonJS 试解析,失败后再按 ESM 重新解析**——每一次插件加载多一次完整文件 IO + parse。

### 修复

新增两个 `package.json`:
- `plugins/agint-rules/package.json`
- `plugins/agint-quality/package.json`(聚合包,`"main": "./agint-quality-contract/lib/index.js"`)

都声明 `"type": "module"` + `"name"` + `"main"` + `"exports"` + `"keywords": ["dsh-plugin", "agint", ...]`。

### 教训

- **Cordis plugin 必须有 `package.json`**,否则触发 Node 性能开销 + 警告噪音。
- AGINT 仓库初始化时应该有个 `scripts/init-plugin.sh` 或 `scripts/ensure-package-json.mjs`,自动给每个 `plugins/*/` 补一个最小 package.json。
- `lint-agint.mjs` 应该加一条 `package-json-required`:每个 plugin 目录必须有 `package.json` + `"type": "module"` + `"main": "lib/index.js"` + `"name": "<dir-name>"`。

## 元教训 — 这次为什么没拦住

1. **`agint-quality-eval` v0.2 提交时(commit 4260fdb),只加了 plugin 源码,漏了 patch 行**——`profile-patches/web/cordis.patch.yml` 里没有它的 `insert` 段。这导致:
   - install.sh 跑到时,把它"自动补上"(因为我重写了 install.sh 的合成逻辑,会把 dst 里没出现的 agint 段自动追加)
   - 但**正确做法**是**写 patch 也要写 plugin 源码,或写自动校验**。
2. **AGINT 仓库缺少 CI / lint 验证 install.sh + plugin patch + plugin 源码三者的同步**——`agint-dsh/scripts/lint-agint.mjs` 只 lint 了 plugin 源码风格,没验证三者一致性。
3. **`docs/plugins/agint-quality-eval.md` 之前只描述 contract**——缺 eval 插件本身的 runbook。补完之后,下次 eval 出问题能直接对照。
