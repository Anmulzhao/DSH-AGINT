# 经验教训 — v0.3 tools/post-execute 瀑布契约崩盘

> 写于 2026-09-04。DSH web 全栈工具调用挂死、所有 preset 报 `Cannot read properties of undefined (reading 'kind')` 的根因排查 + 修复 + 预防机制。**应同步为 memory lesson + pattern 双写**(见文末「沉淀待办」)。

## TL;DR

DSH web 启动后所有 preset、所有 session 的工具调用全部失败。根因是 **agint-event-bus / agint-mount 两个插件各注册了一个 `ctx.on('tools/post-execute', () => {})` 占位监听**。`tools/post-execute` 是 **waterfall(瀑布式)事件**,监听器必须调 `next()` 把链传下去 —— 这两个占位监听既不调 `next()` 又返回 `undefined`,导致瀑布最终结果为 `undefined`,dsh-tools 读 `decision.kind` 抛错。

| 维度 | 内容 |
|---|---|
| 现象 | 任意工具调用 → `Error: Cannot read properties of undefined (reading 'kind')` |
| 触发条件 | web profile 加载后第一次工具调用即触发,所有 preset 全挂(因为这俩插件挂在 profile 级) |
| 根因 | waterfall 监听器没调 `next()` |
| 修复 | 删除两个占位监听 + 加注释说明 waterfall 契约 + 加 lint 维度 9 自动拦截 |
| 持续时间 | ~30 分钟排障 + 5 分钟修复 |

## Bug — waterfall 占位监听静默吞掉瀑布结果

### 现象

`dsh web` 启动后,**任意 preset** 的**任意工具调用**都报同一个错:

```text
Error: Cannot read properties of undefined (reading 'kind')
    at <dsh-tools dist>/lib/types/index.js:3393
    at <dsh-tools dist>/lib/types/index.js:1115
```

最初怀疑是 runtime 层 `executionMode` 返回对象、或者工具管线监听的封装问题,但都对不上。错位在 `dsh-tools/lib/types/index.js` 第 3393 行:

```js
if (Object.hasOwn(decision, "content") && Object.hasOwn(decision, "value")) throw ...;
if (result.isError) throw ...;
// ← 这里的 decision 是 undefined
```

`decision` 来自 `ctx.waterfall('tools/post-execute', exec, result, () => Promise.resolve({ kind: 'accept' }))` —— **返回 `undefined` 说明瀑布链上所有监听器都没返回有效决策**。

### 根因

`plugins/agint-event-bus/lib/index.js` 和 `plugins/agint-mount/lib/index.js` 各有一段:

```js
ctx.on('tools/post-execute', () => { });
```

注释(原 agint-event-bus)写明意图:"占位,便于未来挂 event-bus 上 audit trace"。但 **loader 在挂载阶段不验证监听器契约** —— 因为:

1. **loader 不知道该事件是不是 waterfall**(loader 只关心监听器签名能不能 match emit 参数,不管它要不要调 next)
2. 监听器静默返回 `undefined`,**Cordis 的 waterfall runner 在所有监听器都不返回值时,fallback 也不返回任何东西**(默认结束 = `undefined`)
3. `tools/post-execute` 的契约要求监听器**必须**返回 `PostToolDecision`(`{ kind: 'accept' }` / `{ kind: 'block', feedback }` 等)

DSH web 启动时这两个插件挂在 `profile-patches/web/cordis.patch.yml` 的 profile 级,**对所有 session、所有 preset 生效**,所以一炸全炸。

### 排查路径(对照实验)

| 实验 | 结果 | 结论 |
|---|---|---|
| headless 不加 agint patch,调工具 | ✅ 正常 | 不是 node 版本问题(对照 v22 / v24 都正常) |
| headless + agint patch,调工具 | ❌ 报 `reading 'kind'` | 锁定在 agint patch 层 |
| 删除 event-bus / mount 的占位监听,headless + agint patch | ✅ 正常 | 锁定到这两个插件 |
| grep 全仓 `ctx.on.*tools/post-execute` | 4 个文件 | agint-rules 正确(有 `next()`),event-bus / mount 是空监听 |

### 修复

```diff
- ctx.on('tools/post-execute', () => {
-   // TODO: 未来挂 event-bus 上 audit trace
- });
+ // 注意:不要注册 tools/post-execute 空监听 —— 该事件是 waterfall,
+ // 不调 next() 会令瀑布结果为 undefined,dsh-tools 读 decision.kind 抛错,
+ // 所有工具调用失败。event-bus 不消费工具结果,不监听。
```

提交 `b7d9212` 已推到 GitHub main,运行时副本 `~/.dsh/profiles/web/plugins/` 已同步,`dsh web` 重启验证 12 次工具调用全成功。

## 元教训 — 为什么这次没拦住

1. **8 维度 lint 不覆盖 runtime-contract**。`bin/plugin-check.sh` 的维度 1~8(contract / storage / deps / permissions / lifecycle / tests / docs / changelog)全过 —— 因为**所有文件齐、契约声明齐、README 写好**。但**监听器函数体的运行时契约**(waterfall 必须 next + 返回)不在任何声明字段里,只能扫源码。

2. **loader 不验证监听器契约**。Cordis loader 只检查 `ctx.on(...)` 的事件名和监听器签名匹不匹配 emit,不管监听器体。这是 Cordis 的设计(灵活性 > 安全性),但 AGINT 22+ 个插件同时挂在一个 profile 时,**任何一个错就全挂**。

3. **plugin 同步过程是「爆炸半径最大的一次」**。这次两个占位监听是**早就写在源码里**的(commit 历史可查),但之前 plugin 源码没同步到运行时副本(那时 dsh web 根本起不来),所以**从来没真正运行过**。**首次同步即首次运行即首次炸**。

4. **AGENTS.md 已有插件准入红线(8 维度)+ safe-update SOP,但 SOP 没覆盖「waterfall 契约」** —— 这是 9 维度规范该补的。

## 预防机制(plugin-preflight + lint 维度 9)

新加的第 9 维度 + 5 步 preflight 工作流,核心:

### Lint 维度 9:runtime-contract

`bin/plugin-check.sh` 维度 9 静态扫 `lib/index.js`,检测两类违例:
1. **空体监听器**:`ctx.on('tools/post-execute', () => {})` 或 `async () => {}` —— 不调 next
2. **体非空但没 next() 调用**:监听器体里有逻辑但完全没出现 `\bnext\s*\(`(避免误中 `nextStep` / `nextTick`)

perl 不可用时退到 `node bin/_verify-dim9.js <lib/index.js>`,正则逻辑同源。

已知 waterfall 事件名(`bin/plugin-check.sh` 的 `$waterfall_pat`):
- `tools/pre-execute` (allow / deny / ask)
- `tools/post-execute` (inspect / replace / attach context)
- `tools/ptc-dispatch-log` (持久日志副本的同款约束)
- `agent/pre-step` (UserPromptSubmit 模拟)

**新增 waterfall 事件时同步更新这个列表**。

### Plugin preflight skill(5 步)

新增 `presets/{agint,agint-blockchain,agint-investor}/skills/plugin-preflight/SKILL.md`,触发条件:**任何 plugin 源码变更、新插件创建、cordis.patch.yml 新增 - id 行**。

```
1. lint 全 9 维度    bin/plugin-check.sh --all   (0 fail)
2. 写冒烟 fixture    plugins/<name>/test/smoke.mjs
3. 跑 smoke          node plugins/<name>/test/smoke.mjs   (exit 0)
4. diff + manifest 自查 (9 维度 + README + CHANGELOG + 无裸 timer)
5. safe-update       smoke → mount-patch → restart → cat sentinel.lease
```

崩了就 `plugin → patch → preset` 倒序回滚(详见 `docs/operations/safe-update-sop.md`)。

### 正确写法(waterfall 监听器模板)

```js
// ✅ 正确
ctx.on('tools/post-execute', async (exec, result, next) => {
    const reminder = await observe(exec);
    const downstream = await next();
    if (reminder && downstream.kind === 'block') return {
        kind: 'block',
        feedback: downstream.feedback,
        additionalContexts: prependContext(reminder, downstream.additionalContexts),
    };
    return { ...downstream, additionalContexts: prependContext(reminder, downstream.additionalContexts) };
});

// ❌ 禁
ctx.on('tools/post-execute', () => {});                           // 空体
ctx.on('tools/post-execute', async () => { /* TODO */ });         // 体非空但没 next
ctx.on('tools/post-execute', (exec, result) => { ... });          // 缺 next 参数
```
