# 经验教训 — v0.2 install.sh 安全左移

> 写于 2026-08-20。Sprint 1.5 落地。ROADMAP §5.2 + `docs/security-boundary.md` 的工程化映射。

## TL;DR

`install/install.sh` 从"能跑就行"升级为"安全左移"版本：

| # | 之前 | 之后 |
|---|---|---|
| 1 | `cp -a` 默认跟随 symlink | **rsync `--no-links`** + exclude 列表（防 `node_modules` 软链污染） |
| 2 | `.bak-YYYYMMDD-HHMMSS` 散在原位 | **中央备份目录 `$DSH_HOME/.agint-backups/`** + 数量上限 10 |
| 3 | 失败时 `set -e` 立即退出，半成品留在磁盘 | **trap EXIT + 部分回滚栈**（删新装 + 还原 backup） |
| 4 | 无前置校验 | **`install/agint-security-checks.sh`**（独立可跑，13 项检查） |
| 5 | 装完不验证 | **静态校验**：patch YAML 能解析 + 每个 plugin 有 `package.json` + 每个 preset 有 `agent.cordis.yml` |
| 6 | `--dry-run` 只对 preset/plugin/patch 三个目录生效，patch python heredoc 不参与 | **全链路 dry-run**（包括备份、patch 合并、装后校验） |
| 7 | uninstall 只删 AGINT 装入的，**无回滚能力** | `uninstall.sh --restore [--list-backups] [--restore=<archive>]` |
| 8 | `AGINT_HOME` / `DSH_HOME` 只校验存在 | **realpath 校验 + 拒绝 `..`**（防路径遍历） |

## 安全检查项（13 项，4 类）

`install/agint-security-checks.sh`：

```
path checks:
  ✓ AGINT_HOME 存在 / 绝对路径 / realpath 一致 / 不含 '..'
  ✓ DSH_HOME   存在 / 绝对路径 / 不含 '..'
  ✓ 源就位（presets/ plugins/ cordis.patch.yml）
  ✓ AGINT_HOME 是 git 仓（warn，加 --force 跳过）

runtime checks:
  ✓ rsync / python3 / date / mkdir 可用
  ✓ 磁盘可用空间 ≥ 100MB
  ✓ 备份目录可写（首次会建）
```

返回码：0=全过 / 1=有 fail / 0+warn=warn-only（`--strict` 升级为 fail）。

## rsync --no-links 的关键决定

AGINT 仓里**所有 plugin 的 `node_modules` 都是软链**（指向全局 dsh 安装的 transitive deps，由 `eval/setup.sh` 建）。如果 install 用 `cp -a` 或 `rsync` 默认行为，**软链会被跟随复制**：

- `cp -a` 默认跟随 symlink → 把 dsh 全家桶复制到 `$DSH_HOME/profiles/web/plugins/agint-memory/node_modules/@deepseek-ai/dsh/`（几百 MB）
- `rsync` 默认也跟随 symlink → 同样问题
- `rsync --no-links` → 软链在 dst 保留为软链，但**指向的还是原 target**（`$HOME/.npm-global/...`），不复制实体

`--no-links` 的副作用：若 dsh 装在 `$DSH_HOME` 用户**没有**访问权限，dst 软链会断。但**正常 dsh 用户**装在自己 `$HOME` 下，`$HOME/.npm-global` 可访问，软链可用。

## 中央备份目录的 trade-off

之前 `.bak-YYYYMMDD-HHMMSS` 散在原目录，多了污染源。新设计：

```
$DSH_HOME/.agint-backups/
├── agint-presets-20260820-200139.tar.gz    # tar 打包整个 presets 子目录
├── agint-plugins-20260820-200139.tar.gz    # tar 打包整个 plugins 子目录
└── agint-patch-20260820-200139.tar.gz      # tar 打包 cordis.patch.yml
```

**保留最近 10 个**对应 component 备份，超出删最老（按 mtime）。

**为什么不直接 mv .bak-**：原目录可能有用户手写的非 agint 配置（如自定义 plugin），不能 mv 整个 dst；tar 包好。

## partial-install 回滚栈

每个 step 完成后注册一条回滚指令：

```
PARTIAL_STEPS=("rm_dst|$PRESETS_DST/agint" "rm_dst|$PLUGINS_DST/agint-memory" ...)
```

trap EXIT 时按 reverse 顺序执行：

- `rm_dst|<path>`：rm -rf 新装的 dst（适用于 presets/plugins）
- `restore_backup|<path>`：从 `.bak-current` 还原 patch（用 mv，不用 cp，避免半覆盖）

**注意**：trap EXIT 在脚本成功结尾前必须清空 `PARTIAL_STEPS=()` 并 `trap - EXIT`，否则成功也会回滚。已实现。

## 与 security-boundary.md 的映射

`docs/security-boundary.md` 列了硬约束清单。Sprint 1.5 落地对应：

| security-boundary 条目 | install.sh 落地 |
|---|---|
| 不可修改 L0-frozen 层 | install.sh 不碰 dsh core（只追加 user-patch 段） |
| L0/L1 修改走多签 | install.sh 不自动修改任何被 [AGINT-removed] 注释的段 |
| 备份是 L1 操作 | install.sh 每次覆盖前 tar 备份到中央目录 |
| 审计可追溯 | install.sh 输出 `[AGINT] <action> <from> → <to>`，可被 dsh log 收集 |
| secrets 不进任何文件 | install.sh 不读 / 不写任何 secret |

## 已知限制

1. **patch 合并仍依赖 python3**（不是 rsync / shell） — dsh patch 含 `!!js/function` 自定义 tag，shell 文本处理搞不定。这条限制是从 v0.1.3 留下来的，没在 Sprint 1.5 改。
2. **rsync 在 macOS / Linux / WSL 行为略有差异** — `--no-links` 在三个平台都可用，但 `--delete` 行为有版本差异。Sprint 1.6 跨平台验证会覆盖。
3. **`uninstall.sh` 仍有 plugin 层级误判 bug**（把 `agint-quality-eval` 当独立顶层目录）— 这从 v0.1 沿用，没在 Sprint 1.5 修（Sprint 1.5 范围是 install 端安全，不动 uninstall 业务逻辑）。已记入 follow-up。
4. **静态校验只查"存在性"**，不查"正确性"。比如 `agent.cordis.yml` 存在但内容坏掉不会报。Sprint 2.A `agint-quality-sandbox` 会补动态沙箱执行验证。

## 怎么验

```sh
# 1. 独立跑安全检查
./install/agint-security-checks.sh
./install/agint-security-checks.sh --strict

# 2. 试装（dry-run 不写盘）
./install/install.sh --dry-run

# 3. 看现有 dsh 是否会被改
./install/uninstall.sh --dry-run

# 4. 备份列（首次 install 之后才有）
./install/uninstall.sh --list-backups
```
