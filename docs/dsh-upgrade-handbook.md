# dsh 升级承接手册

> 仓库级方法论文档。回答一个问题：**dsh 每次升级后，AGINT 怎么承接？**
> 定位见 `docs/capability-boundary.md`。本文件只讲流程，不重复边界判据。

---

## 0. 一句话

dsh 升级后，AGINT 做三件事：**发现它变了 → 看它多了什么 → 决定自己少做什么**。

第三件是本手册的重点。前两件是探测，第三件是**克制**。

---

## 1. 为什么需要这份手册

AGINT 是 dsh 的插件集合，不是 fork。它对 dsh 的耦合是三类，全部会随升级断裂：

| 耦合类型 | 形态 | 断裂后的症状 |
|---|---|---|
| 包名耦合 | preset / patch 里写着一串 `@deepseek-ai/dsh-*` 包名 | 整张 preset 拒绝挂载，**UI 只显示加载失败，不落日志** |
| 服务键耦合 | 插件 `inject` / `consumes` 声明宿主服务键 | 插件挂上了但一个工具都没有，**同样不报错** |
| 能力面耦合 | AGINT 自己实现了宿主已提供的能力 | 不报错，但宿主一改就瞎 |

历史上三类都踩过（见 `VERSION` 兼容矩阵与 `capability-boundary.md` §4）。
共同点：**故障不报错**。所以靠人肉 grep 和事后发现，代价是几天到几十天的静默断供。

---

## 2. 七步流程

每次 dsh 升级后照做。前四步是探测，后三步是裁决。

### 第 1 步 · 发现升级

```
node bin/dsh-surface.mjs
```

| 退出码 | 含义 | 动作 |
|---|---|---|
| 0 | 能力面无变化 | 无事，结束 |
| 3 | **宿主版本变了**，能力面未变 | 进第 2 步 |
| 1 | **能力面有增删** | 进第 2 步 |
| 2 | 没查（找不到宿主） | 配 `DSH_HOST_APP_ASAR`，**不要当通过** |

⛔ 退出码 2 不是通过。查不到 ≠ 一致。这是本仓的铁律（`bin/host-version.mjs` 头注释）。

⚠️ 2026-10-25 实测：`0.2.1-rc.2 → rc.3` 服务键 98→98、事件 82→82 **零差异**。
所以「有升级」不等于「有能力面变化」。两层判断缺一不可。
