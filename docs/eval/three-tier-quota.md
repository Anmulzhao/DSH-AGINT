# 三层隔离配额定案（Evolution / Validation / Frozen）

> 状态：**Sprint 18 拍板**（2026-10-02）。本文档是 Phase 1 交付物 1（三层隔离）的分配依据。
> 计量口径：**123 = driver 口径**（不含 `dedicated/`，见
> [scenario-inventory.md](./scenario-inventory.md) 第 3 节）。任何配额计算的分母都是 123。

## 1. 定案

| 层 | 单元数 | 占 123 | 构成 |
|---|---|---|---|
| **Evolution** | 88 | 71.5% | 现有单元，**含 3 个 fail**（满足 H1 的 ≥60%） |
| **Validation** | 31 | 25.2% | 现有单元，**全 PASS**（fail 不放这层） |
| **Frozen** | 10 | 8.1% | **6 个新编写**（60%，满足 H2）+ 2 个 fail 探针 + 2 个 PASS 锚点 |
| 合计 | 123（+6 新编写） | — | 88 + 31 + 4（Frozen 中来自现有 123 的部分）= **123** ✓ |

Frozen 首期占比 **8.1%**（10/123 的分母按现有单元计为 4/123，
按含新编写后的 129 计为 10/129 ≈ 7.8%）。

## 2. H1–H5 约束（含两处修订）

| 约束 | 原文 | 修订后 | 修订性质 |
|---|---|---|---|
| **H1** | Evolution 必须保留 ≥60% 存量 fail | 不变（≥3 个 / 5 个） | — |
| **H2** | Frozen 中 ≥60% 为新编写 | 不变，但 **Frozen 首期占比 15% → 8%** | 主动缩小首期，**不是**降低纯净度 |
| **H3** | Frozen 中存量 fail 探针 ≤4 | **≤2** | ⚠️ **被迫收紧**，见下 |
| **H4** | 每域至少 N 单元才进 Frozen | 不变 | — |
| **H5** | Frozen 只增不减 | 不变 | — |

### 2.1 H3 为什么是被迫收紧（不是主动调整）

存量 fail 实测 **5 个**（不是设计假设的 12 个）。

```
H1 要求 Evolution 保留 ≥60% × 5 = 3 个 fail
⇒ 可供 Frozen 做探针的 fail = 5 − 3 = 2
⇒ H3 上限只能是 2
```

**这是算术结果，不是选择。** 文档必须写明这一点，否则后人会误以为 ≤2 是某种偏好，
进而在 fail 数回升时忘记同步放宽。

### 2.2 H2 为什么缩小首期而不是放宽

15% 的 Frozen = 18 单元，其中 ≥60% 须新编写 ⇒ **要新写 11 个场景**。
这是 Phase 0 里唯一的"创作型"工作量，被严重低估。

且 H2 的理由站得住：现有 123 个单元都在同一个池子里，进化过程全都见过，
严格说**没有一个够格当"冻结"集** —— 所以不能靠放宽 H2 来省事。

**解法是缩小首期 Frozen，而不是降低纯净度。** 新编写量从 11 降到 6。

### 2.3 后续增长路径（H5：只增不减）

| 周期 | Frozen 新增 | 累计 Frozen | 占 123 |
|---|---|---|---|
| 首期（Sprint 19） | 新编 6 + 现有 4 | 10 | 8.1% |
| +1 周期 | 新编 3 | 13 | 10.6% |
| +2 周期 | 新编 3 | 16 | 13.0% |
| +3 周期 | 新编 3 | **19** | **15.4% ≈ 目标 15%** |

**小而真，比大而污染好。**

## 3. 两处必须同时声明的盲区

> 盲区不改结论，但不说出来就是隐瞒。

### 3.1 H4 命中 `dream` 与 `memory` —— 这两个域永远进不了 Frozen

实测 domain 分布（`inventory.json` 的 `summary.domainCounts`）：

```
dream   = 1 单元
memory  = 1 单元
```

低于 H4 的最低样本量 ⇒ **这两个域的能力提升无法被 Frozen 检出**。

- `memory` 域改由 **Phase 2 的 `recall_outcomes` 埋点**评估（这是唯一补救路径）
- `dream` 域目前**无替代评估路径** —— 这是已知且未解决的缺口

### 3.2 `quality` 域占 46.3%（57/123）—— 单域主导风险

```
quality           57  (46.3%)
diagnosis         10  ( 8.1%)
self-model        10  ( 8.1%)
mount              8  ( 6.5%)
pipeline           8  ( 6.5%)
evolution-memory   7  ( 5.7%)
event-bus          6  ( 4.9%)
install-security   6  ( 4.9%)
rules              5  ( 4.1%)
cron               2  ( 1.6%)
metrics            2  ( 1.6%)
dream              1  ( 0.8%)
memory             1  ( 0.8%)
```

若不干预，Validation 与 Frozen 的抽样会被 `quality` 主导，整体指标实际只反映一个域。
⇒ **抽样时应刻意压低 quality 占比**（目标：让其在两层中的占比显著低于 46.3%）。
具体压低幅度与抽样算法在 Phase 1 实现时确定，并须在产出里回写实际占比供核对。

## 4. 反转条件

| 若发生 | 则 |
|---|---|
| 存量 fail 数变化（>5 或 <5） | **重算 H1 配额与 H3 上限**（H3 = fail 数 − ⌈0.6 × fail 数⌉） |
| `dedicated/` 并入 driver 口径 | 分母改 123 → 152（runner 粒度），**重跑全部配额计算** |
| `dream` 域单元数增至 ≥H4 阈值 | 该域纳入 Frozen 抽样，盲区 3.1 解除 |
