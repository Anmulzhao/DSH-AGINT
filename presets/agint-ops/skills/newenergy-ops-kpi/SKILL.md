# 新能源生产运维指标口径与数据字典

> 智进·生产运维 专属 skill。算指标、对口径、查字段时先加载本文件，**不要凭印象填数**。

---

## 0. 最高优先级规则：口径优先级

三级优先级，**从高到低**：

1. **公司/集团考核办法与合同口径** —— 结算依据，绝对最高。哪怕它与本文件不一致。
2. **现行有效的国家/行业/地方标准** —— 条款号与版本需核实。
3. **本文件的通用口径** —— 行业常见算法，**只在 1、2 都没有明确规定时使用**，且必须在产出里注明"按通用口径"。

**执行纪律**：

- 你**不能**自己编一个口径然后当成公司口径用。
- 发现本文件与公司办法冲突时：**以公司办法为准**，并在产出里单独列一行差异提示。
- 不确定标准条款号时，**标注 `[待核实]` 并说明需要查什么**，不要给一个看起来很专业的错误编号。
- 公司口径一旦确认，**写进 wiki 并建立业务偏好 memory**，下次直接用，不再重新讨论。

> ⚠️ 本文件的公式是行业通用写法。**不同业主、不同区域电网、不同设备厂商的统计口径可能不同**，
> 同一指标出现"两个部门算出两个数"是常态。遇到这种情况，先对口径，再对数。

## 1. 核心指标定义与公式

### 1.1 光伏电站

| 指标 | 符号 | 公式 | 单位 | 常见经验区间 |
|---|---|---|---|---|
| 理论发电量 | `E_theo` | 装机容量 × 辐照量 | kWh | — |
| 实际发电量 | `E_act` | 上网电量 + 站内用电（视口径） | kWh | — |
| 系统效率（PR） | `PR` | `E_act / E_theo` | % | 0.75 ~ 0.85（地面电站） |
| 修正系统效率 | `PR_c` | `PR × (1 + γ(T_cell − 25))` | % | 需温度修正 |
| 系统可利用率 | `A_sys` | `1 − (弃电量 + 故障损失量) / E_theo` | % | 98% ~ 99.5% |
| 设备可利用率 | `A_dev` | `(日历时间 − 故障停机时间) / 日历时间` | % | 考核常用，与 `A_sys` 不同口径 |
| 等效利用小时 | `H_eq` | `E_act / 装机容量` | h | 一类资源区 1300 ~ 1600 |
| 弃电率 | `R_cur` | `弃电量 / E_theo` | % | 西北高，南方低 |
| 组件效率 | `η_mod` | `P_max / (辐照 × 面积)` | % | 量产 21% ~ 23% |
| 逆变器效率 | `η_inv` | 直流侧输入 / 交流侧输出 | % | 98% ~ 99% |

**温度修正系数** `γ`（组件功率温度系数，取组件铭牌值，缺省约 −0.0035 ~ −0.005 /℃）：
`PR_c` 算的是标准测试条件（25℃）下的表现，夏季高温会拉低实际 PR，不修正会误判成"设备劣化"。

**辐照量来源优先级**：电站测得辐照计 > 气象站同测点数据 > 卫星/再分析数据（如 ERA5/merra）> 典型值估算。
**不同来源的辐照量可差 5% ~ 10%，PR 会同比例反向偏移** —— 对账争议时第一件事就是核对辐照源。

### 1.2 风电场

| 指标 | 公式 | 单位 | 备注 |
|---|---|---|---|
| 理论发电量 | `E_theo` | kWh | 需风资源数据 + 功率曲线 |
| 风功率利用系数 | `CP` | `E_act / (0.5 × ρ × A × Σv³ × t)` | 无量纲，一般 0.40 ~ 0.50 |
| 风电可利用率 | `A_wind` | `1 − 损失电量 / E_theo` | 见 §1.4 损失分类 |
| 等效利用小时 | `H_eq` | `E_act / 装机容量` | h |
| 弃风率 | 限电损失电量 / 可发电量 | % | 与光伏弃电率同一算法、不同成因 |
| 尾流损失 | 需风场 CFD/WAsP 模拟 | % | 上风向机组的连带损失 |

**CP 的三个常见误判来源**：空气密度 ρ 未按实际温度气压修正、功率曲线选错机型/版本、扫掠面积算错（叶片改造后未更新）。

### 1.3 储能电站

| 指标 | 公式 | 单位 | 备注 |
|---|---|---|---|
| 充放电效率 | `η_rt` | `E_discharge / E_charge` | 直流侧 / 交流侧口径差异大，**必须注明** |
| 循环效率 | 单次循环效率 | % | 功率/容量型号差异显著 |
| 可用容量 | `S_avail` | kWh | `额定容量 × SOH` |
| 容量保持率 | `SOH` | `当前可用容量 / 初始容量` | % |
| 等效满充放次数 | `EFC` | 累计放电量 / 额定容量 | 次 |
| 辅助用电率 | 辅助电 / 放电量 | % | 影响净发电量核算 |

**储能最易吵架的三个数**：效率（直流/交流）、可用容量（铭牌/实测/SOH 折算）、循环次数（等效满充放/实际满充放）。**出报表前先把这三个口径写清楚。**

## 2. 损失电量分解（核心争议区）

这是运维分析里最容易出分歧的部分。**分解必须互斥且穷尽（MECE）**，否则各项之和 ≠ 总损失。

### 2.1 标准分类骨架

```
总损失 = 限电损失（电网调度/弃风弃光）
       + 非计划停机损失（故障）
       + 计划停机损失（检修/技改）
       + 性能损失（组件衰减、逆变器降额、功率曲线偏差、线损）
       + 其他（遮挡、积灰、弃光限发、调试期）
```

**分解步骤**（顺序不能乱）：

1. 先算 `总损失 = E_theo − E_act`。
2. 从**有明确调度指令/时间戳**的记录里扣限电（最硬的数据，优先扣）。
3. 从**停机台账/CMS 工单**里扣故障与计划停机。
4. **剩下的才是性能损失与其他** —— 这一坨通常是争议最大、也最能说明问题的部分。
5. 各项相加必须回到总损失，**差值 > 1% 直接标为"未解释差异"，不强行摊派**。

> ✅ 未解释差异**如实列出**是专业表现；凑数摊派是数据造假。

### 2.2 互斥性检查清单

- 一次停机同时算"故障"和"限电"了吗？（通常应按**主要原因**归一类）
- 计划检修期遇上限电怎么办？（按主因归，另一类记 0 并备注）
- 并网调试期算不算损失？（多数口径单独列"调试期"，不进考核损失）
- 备品替换当天的停机算计划还是故障？（**按公司口径**，这是典型争议点）

## 3. 数据字典：关键字段与单位

### 3.1 通用

| 概念 | 常见字段名 | 常见单位 | 坑 |
|---|---|---|---|
| 装机容量 | `rated_power` / `cap` / ` Installed Capacity` | kWp / kW | **直流装机 ≠ 交流装机**，PV 场景二者不等，报送前确认 |
| 发电量 | `generation` / `E_act` / `ActivePower`(瞬时) | kWh（**不是 kW**） | 瞬时功率与累计电量混淆 |
| 上网电量 | `grid_feed` / `E_grid` | kWh | 与站内用电的口径差 |
| 时间戳 | `ts` / `collect_time` | — | **时区、夏令时、15/30 分钟点功率累加 vs 日冻结值** |

### 3.2 光伏

- 辐照：`G_poa`（倾斜面辐照，**POA 优于水平面 HORIZ**）/ `GHI`（水平面）/ `DNI` / `DIF`；POA 分解用 `Perez` 或 `Hay-Davies` 模型。
- 组件：`module_rated_w`、`p_max_stc`、`temp_module`、`voc`、`isc`、`dc_voltage`。
- 汇流箱/组串：`string_current`、`string_voltage`、`combiner_alarm`。
- 逆变器：`ac_power`、`dc_power`、`efficiency`、`temp_heatsink`、`fault_code`、**`active_power_limit` / `reactive_power_limit`（限发指令证据）**。
- 关键：**组串电流横向对比**是发现遮挡/衰减/失配的最便宜手段。

### 3.3 风电

- 风速：`wind_speed`（**要确认测风高度与位置**，轮毂高度/塔基差异巨大）、风向 `wind_direction`。
- 功率：`active_power`、`rated_power`、`rotor_speed`（变桨 `pitch_angle`、转速 `rotor_speed` 反映限功率）。
- **偏航对风偏差** `yaw_error`、齿轮箱油温、发电机温度、叶片结冰/雷击记录。
- 关键：**实测功率曲线 vs 厂家曲线**的偏差是性能下降判定的基础。

### 3.4 储能

- `soc`、`soh`、`charge_discharge_power`、`cycle_count`、`temperature`（电芯温度异常是安全前提）。
- 关键：**BMS 报警/保护动作记录**与调度指令的时序对齐。

## 4. 常见计算陷阱（每一条都见过真实翻车）

1. **瞬时功率当电量**：`P` 单位 kW，`E` 单位 kWh，15 分钟点累加要乘 0.25 h。
2. **日冻结值 vs 逐点累加**：两者常差 0.1% ~ 1%，差额是停机重启时的点丢失。**同一张表内不要混用两种口径。**
3. **辐照源不一致**：PR 对账翻车的第一大原因。
4. **直流/交流装机容量混用**：直接导致 PR 算错几个点。
5. **闰年/跨年同比**：2 月天数不同，2 月同比必须用**日均**再比。
6. **缺失值当 0 还是剔除**：停机期间辐照照常、发电为 0，若把停机时段从样本剔除，会**高估**整体表现。**分母口径要前后一致。**
7. **百分比变化的分母**：同比/环比要写清分母是哪个量。
8. **STC 温度修正符号**：`γ` 为负值，夏季修正会让 PR 上升，写反了会得出"组件衰减加剧"的错误结论。
9. **容量变更后未分段**：扩容/改造后跨期对比必须分段，或用单位容量指标。
10. **四舍五入层层放大**：Excel 里先四舍五入再乘除，累计误差可达 1% 以上。**中间量不取整，只在展示时取。**

## 5. 计算纪律（本角色不可妥协）

- **先算后写**：任何数字进入文档前，先有可复现的计算过程。
- **中间量不取整**，只在最终展示时按需舍入。
- **每个数字可追溯**：来源文件 + 时间范围 + 口径版本。
- **留痕**：分析脚本存 `<工作目录>/analysis/<日期>-<主题>/`，结果与脚本同放，便于复核与复现。
- **不确定就说不确定**：宁可交"这部分算不了，缺 ×× 数据"，也不要给一个假数。

## 6. 首次使用本口径库时

不要假设公司口径已对齐。**先做一次口径确认**：

1. 向老板要（或在 wiki 里找）现行的**考核办法/统计口径文件**。
2. 列出本文件中与它可能冲突的指标，逐条确认取舍。
3. 把确认结果写入 wiki（`新能源/指标口径-<公司或场站>.md`）与业务偏好 memory。
4. 之后一律按确认口径执行，**不再每份报表重新讨论**。
