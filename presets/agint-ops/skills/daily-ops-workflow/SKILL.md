# 日常工作流

> 智进·生产运维 专属 skill。日常事务最容易变成"老板催一次我动一次"，本文件把它变成固定序列。

---

## 1. 通用原则

1. **先查历史再动手**：`agint_search` 一次查 memory + wiki，确认这个口径/这个坑之前有没有结论。**别重复问老板已经确认过的事。**
2. **结论先落地再汇报**：写进 wiki/文件，再给摘要。聊天记录不算落地。
3. **同一件事做第二次就提自动化**：见 §5。
4. **闭环才算完**：工单、缺陷、整改项没有验证人和闭环日期，就是没做完。

---

## 2. 固定事务的动作序列

### 2.1 晨会（日）

```
① 取昨日数据      发电量、PR、可利用率、限电、异常设备
② 核对未闭环项   昨天遗留的工单/缺陷今天什么状态
③ 汇总异常        按影响排序（不是按时间）
④ 定今日重点     ≤5 条，每条可执行、可验收
⑤ 列协调事项     需要谁配合、什么时候之前给
⑥ 出晨会材料      按 ops-doc-writing §2.1 日报结构
```

**先看数据再开会，不要开会时现查。**

### 2.2 派工与工单跟踪

**派工**：每条工单必须有 **事项 / 责任人 / 截止时间 / 验收标准**。缺任何一项，**当场问清，不要留空进系统**。

**跟踪**（每天一次，不需要老板催）：

```
新建项     昨天新增的工单是否都已派下去？
进行中     卡了几天？卡点是什么？是否需要升级？
到期未闭环 今天到期的，完成了吗？没完成的原因写进台账
逾期       列出逾期清单 + 原因 + 新期限（不接受"再等等"）
```

**催办分寸**：逾期先问原因，别直接催人。原因写进台账，**同一条工单反复逾期要在周报里体现**，而不是私聊了事。

### 2.3 巡检安排

- **频次来源**：按公司规定 / 厂家要求 / 设备状态动态调整。**先查有没有既定规定，不要自己发明频次。**
- **差异化**：新投运设备、故障后恢复设备、长期告警设备 → 提高频次并写明理由。
- **特殊天气/工况后加巡**：大风、暴雨、冰雹、沙尘、覆冰后 —— 这类加巡要有记录。
- **巡检结果要有信息量**：只写"正常"等于没巡。写"正常到什么程度"或"发现什么苗头"。
  见 `ops-doc-writing` §3 的流水账反模式。

### 2.4 整改闭环

```
发现 → 定级 → 定措施（责任到人 + 时间）→ 实施 → 验证 → 关闭
```

**关闭条件是"验证通过"，不是"措施已下发"。** 验证方法要事先写清楚（复测数据、复检签字、观察 N 天无复发）。

**举一反三**：一个设备出问题后，同类设备是否排查过？排查结果要落记录 —— 这是运维体系成熟度的分水岭。

### 2.5 周期性考核与报表

- **口径先确认**（见 `newenergy-ops-kpi` §0），确认一次，之后固定。
- **数据完整性检查**在前，指标计算在后（顺序不能反）。
- **未解释差异如实列出**，不摊派。
- 报表生成过程按 `data-analysis-ops` 留痕。

## 3. 沉淀纪律：双写

| 内容 | 写到哪里 | 例子 |
|---|---|---|
| 结论、口径、定义、SOP、案例、模板 | **wiki** | "本月 PR 下降归因结论"、"设备可利用率口径定义"、"日报模板" |
| 原则、老板的偏好、踩过的坑、禁止项 | **memory**（带证据） | "老板要求报表里必须区分事实与推断"、"不用 pandas，用 csv+numpy" |
| 周期性结果数据 | `analysis/<日期>-<主题>/out/` | 月度汇总表 CSV |

**判断准则**：**"下一个人/下个月的我要用到吗？"** 会用到 → wiki；属于"永远该怎么做" → memory。

**memory 必须带证据**（哪个任务、哪个文件、哪次实际发生），空口原则过两个月自己都不信。

## 4. 与智进母会话的分工

| 事项 | 去哪 |
|---|---|
| 生产运维文档、数据分析、日常事务 | **本会话** |
| DSH / 智进系统故障、插件挂载、preset 组合改动 | 智进母会话 |
| 写代码、改配置、部署 | 智进母会话 |
| 区块链/Web3 相关 | 智进·区块链 子会话 |

**不越界**：本会话不碰 DSH 自身运维，母会话不接日常报表。分不清时问老板。

---

## 5. 自动化：重复性事务不要手动

**同一个动作做第二次，就该考虑交给 cron。**

| 重复事务 | 自动化方式 |
|---|---|
| 每天日报/数据汇总 | `cron` 每天固定时间跑分析脚本 → 生成 out/ → 汇总 |
| 每周工单逾期检查 | `cron` 每周一读台账 → 列出逾期清单 |
| 月度考核报表 | `cron` 每月 1 日跑 → 出草稿 → **人工复核后发出** |
| 指标异常阈值巡检 | `cron` 每日比对 PR/可利用率阈值 → 超限才提醒 |

**自动化的纪律**：

- 自动化产出的东西**必须有人工复核环节**，尤其是对外的文档。
- 自动化**不能替代判断**：异常数据应"提醒"而不是"自动下结论"。
- 定时任务写入/修改前先跟老板确认时间点与产出位置。
- 建好后告诉老板"以后这个时间自动出，不用你催"，并把任务说清楚。

---

## 6. 会话开始时的第一个动作

新会话开工，先跑一次：

```
agint_search "<今天要干的事关键词>"
```

把 wiki 里已有的口径、模板、上次的结论捞出来，**在动手前对齐**，而不是做完了才发现口径不对。
