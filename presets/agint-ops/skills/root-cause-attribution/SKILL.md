# 异常归因方法

> 智进·生产运维 专属 skill。**归因结论必须有证据链**，不许用"可能是…"交差。
> 通用因果推理 4 道关见 `causal-reasoning` 技能，本文件是它在运维场景的落地。

---

## 0. 归因六步法（顺序不可跳）

```
① 数据校验 → ② 现象定义 → ③ 工况分段 → ④ 假设生成 → ⑤ 证据检验 → ⑥ 结论与防复发
```

**最常被跳过、也最致命的是 ①。** 大量"异常"最后查出来是采集问题、时间戳错位、口径不一致 —— 没做过数据校验的归因等于在猜。

---

## ① 数据校验：先证明数据可信

在下任何结论之前，逐项确认：

- [ ] **时间对齐**：监控数据、故障记录、调度指令、工单的时间戳是否同一时区、同一采样频率？
- [ ] **完整性**：异常时段的点数据是否缺失？缺失是"没采到"还是"真为 0"？
- [ ] **量纲与单位**：kW / kWh、日冻结值 / 逐点累加，是否混用？
- [ ] **口径**：比较的两个指标是否同一口径（直流/交流装机、站内/上网电量）？
- [ ] **基线合理性**：同期值、历史同工况值、厂家理论值的数量级是否吻合？

**红线**：数据校验没过，**不要输出归因结论**，只输出"数据不足以支撑归因，缺 ××"。

---

## ② 现象定义：把"效率低"翻译成可测量的差异

模糊的现象不能归因。必须量化：

- ❌ "最近发电量偏低"
- ✅ "9 月 3 日至 9 月 10 日，3# 逆变器日均 PR 为 0.71，同期全场均值 0.79，偏差 −10.1%（已剔除辐照源差异，两次均用同一测点）"

**指标 + 时间范围 + 对比基准 + 偏差幅度**，四要素齐全才算现象定义完成。

---

## ③ 工况分段：三类因素必须分开

同一台设备的表现差异，根因可能完全不同。按顺序排查：

| 类别 | 含义 | 判别方法 |
|---|---|---|
| **资源因素** | 辐照/风速/温度/云量等天然波动 | 同期同区域其他场站/相邻方阵/相邻机组对比 |
| **设备因素** | 组件衰减、失配、逆变器、齿轮箱、电池老化 | 同场站同类设备横向对比（关键） |
| **运行因素** | 限发指令、运行方式、检修、误操作 | 查调度指令、操作票、检修计划时间戳 |

**横向对比是运维归因最强的武器**：同一场站的同类设备处于相同资源条件下，差异只可能来自设备或运行。

---

## ④ 假设生成：穷举 + 排序

按"常见度 × 影响度"列候选假设，**每个假设写成可判定的形式**：

- ❌ "可能是组件问题"
- ✅ "假设：3# 逆变器 6# 组串电流较同方阵其余组串低 ≥15%，且与辐照变化无关（比值恒定）"

可判定的假设才能被证伪。**比值恒定**这类判据是衰减/失配/遮挡的典型特征（见 §5 鉴别表）。

---

## ⑤ 证据检验：过因果推理 4 道关

用 `causal-reasoning` 的 4 道关逐条过：

1. **相关 vs 因果**：时间先后是否成立？有没有第三方变量（季节、检修、限电）同时影响？
2. **反事实**：如果没有这个原因，异常是否仍会发生？
3. **剂量**：原因强度与异常幅度是否匹配？（小扰动解释不了大偏差）
4. **第三方变量**：是否遗漏了共同原因？

**证据强度分级**（写报告时标明级别）：

| 级别 | 证据 | 可下的结论 |
|---|---|---|
| A | 复现实验或受控对照，偏差可重复 | 确认根因 |
| B | 多源数据一致（监控+现场+工单），时序吻合，排除他因 | 高置信度判定 |
| C | 单一数据源 + 合理机制解释 | 疑似，写明置信度与验证方法 |
| D | 仅时间相关，无机制解释 | **不得写成根因**，只能写成"待查线索" |

---

## ⑥ 结论与防复发

结论必须包含：

1. **根因**（机制层，不是现象层）+ 证据级别
2. **影响量化**（损失电量/停机时长/设备寿命影响）
3. **已采取措施 + 验证结果**（改了以后指标是否回来了）
4. **防复发措施**：责任人 + 节点 + **可验证的判据**（如"连续 7 天同工况比值 ≥0.95"）

**"加强巡检""提高重视"不是防复发措施** —— 它不可验证、不可考核。

## 5. 场景根因清单与鉴别特征

### 5.1 光伏

| 现象 | 候选根因 | 关键鉴别特征 |
|---|---|---|
| 单组串电流偏低 | 遮挡（烟尘/树木/建筑）、积灰、组件失配/衰减、接头电阻、遮挡热斑 | **与辐照的比值恒定偏低**；横向对比定位；红外热成像可见温差 |
| 全部组串偏低 | 汇流箱/直流线故障、组串接入错误 | 全组串同步变化，告警集中 |
| 单机 PR 下降且随温度升高加剧 | 组件衰减、热斑、遮挡 | 与温度相关性显著 |
| 逆变器效率下降 | 散热/风扇故障、器件老化、MPPT 异常、输入电压超限 | 效率-温度曲线形状改变；告警码 |
| 出力长期被限制 | 限发指令（有功限值）、AGC/AVC 调度 | 查 `active_power_limit` 与调度时间戳对齐 |
| 同型机组差异扩大 | 清洗周期执行差异、备件批次差异 | 与运维记录比对 |
| 每日固定时间掉电 | 定时任务/误操作/控制策略 | 掉电时间点高度规律 |
| 清洁电价时段不发电 | 逆变器夜间自检/并网限制策略 | 查厂家策略配置 |

**横向对比的黄金动作**：同方阵各组串电流排序、`Pmax` 实测与铭牌对比、逆变器之间效率对比。**三个动作能筛掉大部分"疑似设备问题"。**

### 5.2 风电

| 现象 | 候选根因 | 关键鉴别特征 |
|---|---|---|
| 功率曲线偏差（实测低于厂家） | 叶片脏污/侵蚀、偏航对风偏差、齿轮箱损失、发电机冷却、性能功率降额 | 桶装(bin)归一化后对比；实测 vs 厂家曲线分风速段 |
| 特定风速段出力异常 | 特定工况的部件性能问题、控制策略切换点 | 分风速段（3~8 / 8~12 / 12~25 m/s）单独看 |
| 温度频繁报警 | 齿轮箱油温高、发电机温度高、散热系统、轴承磨损 | 报警与负荷/温度的相关性；历史趋势 |
| 频繁停机 | 变频器故障、液压系统、变桨系统、电气保护 | 停机代码 + 频次统计 |
| 可利用率下降但无明确故障 | 计划检修占比上升、备件不足、人员配置 | 检修台账 + 停机原因分类统计 |
| 特定风向出力下降 | 尾流、扇区干扰、机位布局 | 按风向分箱统计 |
| 叶片结冰/雷击 | 结冰风险区、雷电密度 | 气象数据 + 事件记录 |

**必做动作**：实测功率曲线与厂家曲线**分风速段**对比（整体对比会掩盖局部问题）；偏航对风偏差统计。

### 5.3 储能

| 现象 | 候选根因 | 关键鉴别特征 |
|---|---|---|
| 可用容量下降 | SOC 漂移、容量衰减、温度长期偏高、 BMS 校准不准 | 满充满放实测容量 vs 显示值；温度与容量的相关性 |
| 充放电效率下降 | PCS 损耗、线损、辅助用电增加、电芯一致性变差 | 分段损耗拆解（电池/PCS/线损/辅助） |
| 充放电功率受限 | 功率限值设置、温度保护、SOC 区间限制、故障降额 | 查功率限值设置与保护动作记录 |
| 频繁 BMS 保护 | 电芯一致性差、温度传感异常、BMS 通信问题 | 告警时序 + 遥测数据对齐 |
| 循环次数异常 | 策略过于激进、深度充放、待机自放电高 | 策略配置 + 空载电压/电流监测 |
| 响应时间不达标 | PCS 控制延迟、策略限幅、AGC 下发异常 | 指令下发与响应时序打点 |

**必做动作**：把损耗**分段拆解**（电池→PCS→线损→辅助），"效率下降"这种笼统结论无法指导整改。

---

## 6. 归因结论的输出格式

```markdown
## 归因结论

**现象**：（指标 + 时间范围 + 对比基准 + 偏差幅度）
**影响**：（损失电量 / 停机时长 / 设备影响）
**根因**：（机制层描述，标注证据级别 A/B/C/D）
**证据链**：
  1. 数据来源与校验结论
  2. 横向对比结果
  3. 时序吻合性
  4. 已排除的假设及排除依据
**已采取措施**：（做了什么 + 验证结果）
**防复发**：（措施 | 责任人 | 节点 | 验证判据）
**仍不确定的部分**：（如果有，写【待确认】）
```

**"仍不确定的部分"这一栏不许省。** 写清楚剩余不确定性，比给一个滴水不漏但错误的结论有价值得多。
