# 运维文档写作规范

> 智进·生产运维 专属 skill。**动笔前先读本文件**，不按自创格式写文档。

---

## 0. 三条硬规则

### 0.1 事实、推断、待确认 —— 必须分开写

这是本规范的核心。运维文档最常见的失效方式，是把**推测写成陈述**，半年后没人分得清哪个数是量出来的、哪个是猜的。

强制在文档中分区（用小标题或标注，不要混在段落里）：

| 类别 | 标注方式 | 允许的来源 |
|---|---|---|
| **事实** | 常规陈述 | 监控数据、台账、实测、已确认的调度指令 |
| **推断/判断** | `【推断】…（依据：…）` | 明确写出依据与置信度 |
| **待确认** | `【待确认】…（需 ×× 提供）` | 明确写出卡在谁那里、需要什么 |

**禁止**：把"可能是逆变器问题"写成"逆变器故障"；把"预计损失 2000 kWh"写成"损失 2000 kWh"。

### 0.2 结论先行

开头就给判断和数字，过程与依据放后面。老板的时间是稀缺的。

- ✅ "本月发电量 1,284 万 kWh，同比 +3.2%；系统可利用率 98.6%，同比 −0.4 个百分点，主因是 2 次组串故障（损失约 3,100 kWh）。"
- ❌ "本月运行情况总体平稳。发电量方面……（800 字后出现数字）……"

### 0.3 每个数字标来源

`（数据来源：EMS 上网电量表，2026-09-01~09-30）`

口径不明就先查 `newenergy-ops-kpi` 技能，不要凭印象写。

## 1. 动笔前三问

写任何文档前确认（**上下文已明确的不要重复问**）：

1. **给谁看**？（班组 / 部门 / 上级 / 业主 / 监管）—— 决定详略与措辞。
2. **拿来干什么**？（存档 / 考核 / 决策 / 追责 / 交接）—— 决定重点与证据强度。
3. **覆盖什么时间范围/对象**？—— 决定取数边界。

三问都明确就直接写，别拿这些去问已经说过的事。

## 2. 文档结构模板

### 2.1 日报（班组级，信息密度优先）

```
【日期 | 场站/区域 | 天气 | 汇报人】

一、运行概况
   发电量 / 日发电量、峰值出力、系统效率 PR、可利用率、限电情况
   （数据来源：…）

二、异常与缺陷
   逐条：设备编号 → 现象 → 影响（损失电量/停机时长）→ 状态 → 责任人 → 计划完成时间

三、处理进展
   今日已处理 / 待处理 / 需外部协调（写明卡在谁那里）

四、明日重点
   ≤5 条，每条可执行

五、需协调事项
   需要谁、做什么、什么时候之前
```

**日报禁忌**：写成流水账（"巡检了 12 台逆变器，运行正常"）没有信息量。**每条要写"正常到什么程度"或"异常在哪"**。

### 2.2 周报（部门级）

```
一、本周指标概览        —— 发电量、PR、可利用率、故障次数、限电，与上周/同期对比
二、异常与事件          —— 按影响排序，不按时间排序
三、闭环进度            —— 上周遗留项逐条状态（已完成/进行中/逾期，逾期写原因）
四、下周计划            —— 工单、检修、技改
五、风险预警            —— 天气、来电、物资、人员、备件
```

**周报的价值在"对比"和"闭环"**，不在罗列本周做了什么。环比、同比、趋势至少给一个。

### 2.3 月报 / 生产考核报表

```
一、指标完成情况        —— 目标 vs 实际 vs 差异 vs 差异率（用表）
二、损失电量分解        —— 按 newenergy-ops-kpi §2 的 MECE 分类，合计对齐
三、未解释差异说明      —— 有就如实列，差值 >1% 必须说明
四、故障与停机统计      —— 次数、时长、Top 设备
五、限电情况            —— 指令时间、原因、有据可查的证据
六、下月改进项          —— 责任人 + 时间节点
```

### 2.4 异常（缺陷）报告

按**影响程度分级**，不同级别要求的深度不同：

| 级别 | 判据（示例，需按公司标准校准） | 报告要求 |
|---|---|---|
| 严重/事故 | 涉及人身安全、起火、重大设备损毁、长时间全站停运 | 立即口头上报 + 24h 内书面，含时间线、初步原因、损失、已采取措施 |
| 较大 | 单机/单区域停运超约定时长，发电量显著损失 | 当日书面，含时间线、原因、损失、措施、责任人 |
| 一般 | 短时停运、性能下降、告警反复 | 记入缺陷台账，周报汇总，月度分析 |

**每份异常报告的最小要素**（缺一不可）：

1. **时间线**（精确到分钟）：发现 → 上报 → 处置 → 恢复 → 原因确认 → 闭环
2. **影响量化**：停机时长、损失电量、影响范围
3. **直接原因**（现象层面）与**根本原因**（机制层面）分开写 → 详见 `root-cause-attribution`
4. **已采取措施**与**验证结果**
5. **防止再发**的措施 + 责任人 + 完成时间

**"根本原因"不能写"人员疏忽""设备老化"了事** —— 那是现象不是根因。要问：为什么会有这个疏忽/为什么老化到这个程度没被发现？追到机制层。

### 2.5 事故报告

在异常报告基础上增加：

- **应急处置过程评估**：响应是否及时、处置是否得当、预案是否有效
- **影响与责任认定**（按公司流程，不越权下结论）
- **整改计划**：分"立即整改""短期整改""长期整改"，逐条挂责任人与节点
- **举一反三**：同类风险在其他设备/场站是否排查过，排查结果
- **经验教训**：写入 wiki，形成可复用条目

### 2.6 交接班记录

```
交接时间 | 交班人 | 接班人
一、设备状态     —— 异常设备逐条：编号、现象、是否需持续监视
二、未完成作业   —— 作业内容、进度、安全措施、交待事项
三、备件与物资   —— 缺件、借用、待归还
四、注意事项     —— 天气、来电计划、调度要求
五、遗留问题     —— 上班未闭环项，写明卡点
```

**交接班的核心是"未闭环项"，不是"今天干了什么"**。接班人能在 30 秒内知道"现在最该盯的是什么"就算合格。

### 2.7 SOP / 作业指导书

必须包含：

1. **适用范围** + **作业前提条件**（停机、隔离、验电、许可）
2. **危险点与安全措施**（高处、带电、受限空间、机械伤害 —— 电力场景必写）
3. **工具与备件清单**
4. **作业步骤**（可勾选、可逐条核对）
5. **验收标准**（做完怎么算合格，可量化）
6. **异常处置**（出现什么情况立即停止并上报）
7. **记录表模板**（做完留什么记录）

**SOP 的检验标准**：一个没参与过撰写、但有基本经验的人，照着能独立做完，且不会做错。

### 2.8 台账

台账是**结构化数据**，不是流水记录。字段先定好，再填值。

| 台账 | 必备字段 |
|---|---|
| 设备台账 | 设备编号、型号、厂家、投运日期、容量/参数、位置、责任人、状态、技术档案位置 |
| 缺陷台账 | 编号、设备、发现日期、现象、等级、影响、状态（待处理/处理中/已闭环/挂起）、责任人、闭环日期、验证人 |
| 检修台账 | 计划/实际时间、检修内容、备件消耗、发现问题、工时、验收人 |
| 备件台账 | 名称、规格、数量、库位、最小库存预警、领用记录 |

**台账的纪律**：编号规则统一；状态取值受控（不要出现"处理中""正在弄""跟进"三种自由文本）；**闭环必须有验证人和日期**，不能只写"已处理"。

### 2.9 会议纪要

```
时间 | 地点 | 参会人 | 主持 | 记录人
一、议题与结论        —— 每个议题一段，结论加粗
二、待办事项          —— 事项 | 责任人 | 截止时间（必须都有，缺一项就当场问）
三、分歧与未决        —— 没达成一致的，明确写"未决"及下次决策时间
```

**不写纪要的会等于没开**。只记结论不记待办的纪要没有执行价值。

## 3. 常见毛病与改法

| 毛病 | 症状 | 改法 |
|---|---|---|
| 流水账 | 大量动词流水，无数字无判断 | 每条至少带一个数字或一个状态词 |
| 结论后置 | 结论在末尾 | 结论提到第一段 |
| 推测当事实 | "因设备老化导致" | 写现象 + 【推断】+ 依据 |
| 数字无来源 | 出现"较上月提升明显" | 补来源、对比基准、数值 |
| 口径混用 | 同文用两套可利用率定义 | 全文统一口径并注明 |
| 隐患不报 | "运行正常"掩盖小异常 | 单列"观察项"，小问题也记录 |
| 整改无闭环 | 写"已整改"无验证 | 补验证方式 + 验证人 + 日期 |
| 责任模糊 | "已通知相关人员" | 写清通知了谁、谁负责、什么时候完成 |

## 4. 交付纪律

- **文件命名**：`YYYY-MM-DD-文档类型-范围[-版本].md`（或老板指定的格式，按实际约定，不自创）。
- **产出位置**：默认写在工作目录的 `docs/` 下；发布/归档前先确认位置。
- **修改既有文档前先读**：改动已有台账/报告前，先读现状并说明将改哪几处 —— 覆盖生产台账属于需要确认的操作。
- **写完自查**：事实/推断/待确认是否分区？数字是否都有来源？口径是否与 `newenergy-ops-kpi` 一致？待办是否都有责任人和时间？
