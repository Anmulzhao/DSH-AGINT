# 因果推理（Causal Reasoning）

OpenClaw 版 curiosity-engine 有 25 个脚本；DSH 版砍到一份清单 + 一组问题。原则：**模型自觉问自己 + 工具查事实**，不靠脚本堆叠。

## 我是谁 / 边界

- **适用**：排障定位根因、性能下降归因、"该不该做某事"的风险评估、写复盘时区分相关与因果。
- **不适用**：纯描述性问答（"X 是什么"）、纯执行任务（"帮我跑 X"）、创造性任务（设计新 UI / 写新故事）。
- 砍掉的 25 脚本 = 大部分是用不上的"工具检查清单"，问自己 4 道关已经覆盖。

## 4 道关（每次"X 导致 Y"声明之前必过）

### 关 1：相关还是因果？

- 数据上 X 与 Y 同向变化 ≠ X 导致 Y。可能：共同原因 Z、Y 导致 X（反向因果）、纯巧合。
- 自问：**有没有第三方变量 Z 同时驱动 X 和 Y？**
  - 排查方法：在 X 不变的情况下，Y 还变不变？拉长时间窗口，看 Z 是否先行。

### 关 2：反事实

- "如果没有 X，Y 还会发生吗？"
- 把这句话写到复盘里。如果你答不出"不会"，那 Y 至少不只由 X 决定 → 写"主要因素之一"而不是"X 导致 Y"。

### 关 3：剂量

- "X 多 → Y 多吗？"
- 没有剂量响应的因果主张 = 弱相关。例如"这次 bug 用了 X"≠"X 导致这类 bug"。

### 关 4：第三方变量（隐藏原因）

- 显式列出至少 1 个可能的 Z。例如："页面慢了"——Z 可以是：CDN 故障、CPU 飙高、DNS 解析变慢、其它租户抢占。**不只查第一假设**。

## 与工具的接口

| 触发 | 工具 | 作用 |
|---|---|---|
| 排障前 | `memory_search` | 查既有教训（同类问题是否踩过） |
| 高风险操作前 | `rule_check` | 查规则门禁（系统半强制提醒） |
| 不确定路径 | `wiki_search` | 查既有知识（避免重新发明轮子） |
| 改完代码后 | 复盘回到 4 道关自评 | 写复盘文档 |

## 输出格式（复盘 / 归因 / 提案时）

```
** 现象 **
- 看到了什么

** 候选原因（至少 2 个）**
1. A（理由：…）
2. B（理由：…）

** 反事实检验 **
- 如果没有 A，B 还能解释现象吗？→ …

** 隐藏变量（至少 1 个）**
- Z：…

** 结论（带不确定性）**
- 最可能：A（置信度 …）
- 待验证：再做 X 实验 → 看 Y 是否变
```

## 不要做的事

- 不要给"X 出现 → Y 出现"直接写"X 导致 Y"（跳关）。
- 不要只列一个候选原因就定论（缺乏竞争假设）。
- 不要把"我觉得"当证据 — 必须有可观测 / 可复现的来源。

## 与其他技能的关系

- 教训沉淀（"以后不能这样"）→ 用 `memory-discipline` 写 lesson + evidence。
- 流程方法（"排查步骤应该是…"）→ 准则层（AGENTS）。
- 通用知识（"这个组件的工作原理"）→ `agint-wiki` 工具写到 wiki。
- 本技能只负责"决策前怎么想"，不负责沉淀。
